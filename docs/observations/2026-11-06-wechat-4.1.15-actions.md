# 真机动作观察记录：微信 Mac 4.1.15（2026-11-06）

用途：设计"手"的动作前的实测依据，见记忆 `observe-before-designing-actions`。
方法：
- 用户在**示例群**里手动操作，机器人停着，远端每秒约 1.4 帧截屏。
- 只保留聊天区，会话列表在远端就裁掉。
- 搜索下拉的画面只在微信 Mac 上做 OCR，非白名单的文字一律打码。
- 截图用完即删，这里只留文字记录。

环境：屏幕 1280×1024（非 Retina）。录屏过程中微信窗口从 (195,101) 被挪到了 (131,25)，大小 880×640，所以**不能假设窗口位置固定**。

## 1. 收到文件（.xls，27.4M）

| 阶段 | 卡片 / 界面 |
|---|---|
| 刚发出 | 文件名 + `27.4M` + **对方上传中**（无进度条） |
| 约 4 秒后 | 文件名 + `27.4M` + **未下载** |
| 右键卡片 | 菜单从上到下：下载 / 转发... / 收藏 / 多选 / 提醒 / 引用 / **下载到...** / 删除（红） |
| 点"下载到..." | 系统保存窗口：**存储为**里预填原文件名，**标签**栏为空，位置下拉默认"桌面"，下方是 **取消 / 存储** 两个按钮 |
| 点"存储"后 | 卡片只剩文件名 + `27.4M`，**没有任何状态字样**（没有"已下载"），也没有进度条；文件出现在所选文件夹，字节数 28762112 |

结论：
- 文件菜单里**没有"另存为"**，只能用"下载到..."。
- "对方上传中"时不动手。
- 判断下载完成，不能等"已下载"字样，要以"未下载"消失、加上目标文件夹里出现大小稳定的文件为准。
- 菜单里的"下载"不弹保存窗口，文件落进微信自己的数据目录，**不用**。
- **下载后微信会多开一个下载小窗口**：360×124，属于微信进程，layer 0，alpha 1。
  - 里面显示文件名、`27.4M` 和"已下载"，右侧有一个按钮，可能是关闭或打开文件夹。
  - 这个窗口**一直不会自己消失**，下载完成一个多小时后仍然开着。
  - 画面闸门因此判定为 `screen_not_main:other_wechat_window`，机器人会一直等待。
  - 所以手在下载完成后必须负责关掉它，或者把它识别为"下载窗口"后放行。这一步的具体做法也要先在真机上观察再写。

## 5. 搜索进入会话（输入"示例群"）

| 步骤 | 实际看到的 |
|---|---|
| 点击搜索框 | 列表顶部弹出小面板："搜索网络结果"和"最近在搜"，下面的会话列表仍可见 |
| 输入过程中 | 列表被搜索结果替换，按分组排列：一次是"群聊"分组在最上面，示例群是第一行，下方是"聊天记录"分组 |
| 某一刻 | 下拉变成**搜一搜联想词**："Q 示例群""Q 示例群组""Q 示例群在哪里可以找到"……，点了会打开网络搜索 |
| 另一次 | "联系人"分组在前，"群聊"分组在下方，示例群出现的位置低得多；其他群下面显示"包含：<成员名>" |
| 点示例群这一行 | 进入会话，列表恢复；标题显示"示例群(3)"，结果行显示"示例群"，没有人数 |

结论：
- 结果的位置不固定，要按分组标题（群聊 / 联系人）定位；
- 只在该分组里找名字完全相同的那一行；
- 跳过"Q "开头的联想词和"包含："这类行；
- 进入后核对标题，去掉"(人数)"再比对。

## 6. 输入框：全选替换与清空（2026-11-07，示例群，人工按键录屏）

| 操作 | 输入框 | 聊天区 |
|---|---|---|
| 输入框里已有"旧草稿"，按 ⌘A | "旧草稿"整段高亮 | 不变（⌘A 不会选中聊天记录） |
| 接着按 ⌘V | 整段被剪贴板内容替换 | 不变 |
| 再按 ⌘A，然后按删除键 ⌫ | 清空，显示占位提示"按住鼠标 语音输入文字" | 不变 |

结论：
- 发送前先点输入框，按 ⌘A 再按 ⌘V，就能替换掉任何残留草稿，不会把草稿追加在前面；
- 发送失败（没有按回车）时，按 ⌘A 再按 ⌫ 清空输入框，不会留下残余；
- 输入框为空时会显示占位提示。读回核对要用剪贴板（⌘A ⌘C），不能用截图识别文字，否则会把占位提示当成正文。

同一天还确认了两件事：
- System Events 代按的按键已经送不到微信；改用动作组件直接发送键盘事件后，⌘V 和回车都有效（提交 1686dd3）；
- 由 launchd 或访达启动的进程没有 LANG 环境变量，`pbcopy` 会把中文写成乱码（提交 b700188 已修）。

## 7. P1 验收（2026-11-07，部署合并提交 63a12ff）

- 发文字改为 `wechat_click input-text`（NSPasteboard 加动作组件按键）后，部署后的 3 次发送都成功：示例联系人甲 02:36，示例群 04:15、04:17。状态均为 triggered，没有失败。
- 用户在示例群确认结果正常：
  - 输入框里的草稿被整段替换，没有跟着回复一起发出；
  - 回复里的换行和表情正常；
  - 剪贴板里原来的图片在发送后恢复了。
- 还没在真机上验证：
  - 发送文件；
  - 搜索进入会话这条兜底路径；
  - 读回失败时清空输入框。
- 已知的小问题（以前就有）：发送后 `client_echo_observed` 一直是 false，也就是说发出的回复没有在随后的截图里被认出来。
