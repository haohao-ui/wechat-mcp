# 真机动作观察记录：微信 Mac 4.1.15（2026-11-06）

用途：设计"手"的动作前的实测依据，见记忆 `observe-before-designing-actions`。
方法：
- 用户在**示例群**里手动操作，机器人停着，远端每秒约 1.4 帧截屏。
- 只保留聊天区，会话列表在远端就裁掉。
- 搜索下拉的画面只在微信 Mac 上做 OCR，非白名单的文字一律打码。
- 截图用完即删，这里只留文字记录。

环境：屏幕 1280×1024（非 Retina）。录屏过程中微信窗口从 (195,101) 被挪到了 (131,25)，大小 880×640，所以**不能假设窗口位置固定**。

## 1. 收到文件（.xls，27.4M）

| 阶段 | 卡片 / 界面 |
|---|---|
| 刚发出 | 文件名 + `27.4M` + **对方上传中**（无进度条） |
| 约 4 秒后 | 文件名 + `27.4M` + **未下载** |
| 右键卡片 | 菜单从上到下：下载 / 转发... / 收藏 / 多选 / 提醒 / 引用 / **下载到...** / 删除（红） |
| 点"下载到..." | 系统保存窗口：**存储为**里预填原文件名，**标签**栏为空，位置下拉默认"桌面"，下方是 **取消 / 存储** 两个按钮 |
| 点"存储"后 | 卡片只剩文件名 + `27.4M`，**没有任何状态字样**（没有"已下载"），也没有进度条；文件出现在所选文件夹，字节数 28762112 |

结论：
- 文件菜单里**没有"另存为"**，只能用"下载到..."。
- "对方上传中"时不动手。
- 判断下载完成，不能等"已下载"字样，要以"未下载"消失、加上目标文件夹里出现大小稳定的文件为准。
- 菜单里的"下载"不弹保存窗口，文件落进微信自己的数据目录，**不用**。
- **下载后微信会多开一个下载小窗口**：360×124，属于微信进程，layer 0，alpha 1。
  - 里面显示文件名、`27.4M` 和"已下载"，右侧有一个按钮，可能是关闭或打开文件夹。
  - 这个窗口**一直不会自己消失**，下载完成一个多小时后仍然开着。
  - 画面闸门因此判定为 `screen_not_main:other_wechat_window`，机器人会一直等待。
  - 所以手在下载完成后必须负责关掉它，或者把它识别为"下载窗口"后放行。这一步的具体做法也要先在真机上观察再写。

## 5. 搜索进入会话（输入"示例群"）

| 步骤 | 实际看到的 |
|---|---|
| 点击搜索框 | 列表顶部弹出小面板："搜索网络结果"和"最近在搜"，下面的会话列表仍可见 |
| 输入过程中 | 列表被搜索结果替换，按分组排列：一次是"群聊"分组在最上面，示例群是第一行，下方是"聊天记录"分组 |
| 某一刻 | 下拉变成**搜一搜联想词**："Q 示例群""Q 示例群组""Q 示例群在哪里可以找到"……，点了会打开网络搜索 |
| 另一次 | "联系人"分组在前，"群聊"分组在下方，示例群出现的位置低得多；其他群下面显示"包含：<成员名>" |
| 点示例群这一行 | 进入会话，列表恢复；标题显示"示例群(3)"，结果行显示"示例群"，没有人数 |

结论：
- 结果的位置不固定，要按分组标题（群聊 / 联系人）定位；
- 只在该分组里找名字完全相同的那一行；
- 跳过"Q "开头的联想词和"包含："这类行；
- 进入后核对标题，去掉"(人数)"再比对。

## 6. 输入框：全选替换与清空（2026-11-07，示例群，人工按键录屏）

| 操作 | 输入框 | 聊天区 |
|---|---|---|
| 输入框里已有"旧草稿"，按 ⌘A | "旧草稿"整段高亮 | 不变（⌘A 不会选中聊天记录） |
| 接着按 ⌘V | 整段被剪贴板内容替换 | 不变 |
| 再按 ⌘A，然后按删除键 ⌫ | 清空，显示占位提示"按住鼠标 语音输入文字" | 不变 |

结论：
- 发送前先点输入框，按 ⌘A 再按 ⌘V，就能替换掉任何残留草稿，不会把草稿追加在前面；
- 发送失败（没有按回车）时，按 ⌘A 再按 ⌫ 清空输入框，不会留下残余；
- 输入框为空时会显示占位提示。读回核对要用剪贴板（⌘A ⌘C），不能用截图识别文字，否则会把占位提示当成正文。

同一天还确认了两件事：
- System Events 代按的按键已经送不到微信；改用动作组件直接发送键盘事件后，⌘V 和回车都有效（提交 1686dd3）；
- 由 launchd 或访达启动的进程没有 LANG 环境变量，`pbcopy` 会把中文写成乱码（提交 b700188 已修）。

## 7. P1 验收（2026-11-07，部署合并提交 63a12ff）

- 发文字改为 `wechat_click input-text`（NSPasteboard 加动作组件按键）后，部署后的 3 次发送都成功：示例联系人甲 02:36，示例群 04:15、04:17。状态均为 triggered，没有失败。
- 用户在示例群确认结果正常：
  - 输入框里的草稿被整段替换，没有跟着回复一起发出；
  - 回复里的换行和表情正常；
  - 剪贴板里原来的图片在发送后恢复了。
- 还没在真机上验证：
  - 发送文件；
  - 搜索进入会话这条兜底路径；
  - 读回失败时清空输入框。
- 已知的小问题（以前就有）：发送后 `client_echo_observed` 一直是 false，也就是说发出的回复没有在随后的截图里被认出来。

## 8. 通讯录（2026-11-08，专用 Mac，只读探测）

探测方式：在专用 Mac 本机截图 + 本机 Vision 识别，非界面固有文字一律打码，联系人信息没有离开本机；探测期间机器人已暂停，结束后恢复并删除探测程序。坐标均为微信主窗口内坐标（窗口 880×640）。

- **辅助功能树几乎为空**：主窗口只暴露关闭/缩小/全屏三个按钮，列表、分组、资料卡都不在树里。读取只能截图 + 文字识别，点击只能按坐标。
- **左侧导航栏**（x≈30，用户 2026-11-08 截图标注确认）：头像 y≈69、**对话** y≈121、**通讯录** y≈169、**收藏** y≈217、**发现** y≈263；底部：**文件传输助手**（手机形图标）y≈557、**更多设置**（≡）在其下方。点通讯录图标即切换，点对话图标即返回。机器人只允许点"对话""通讯录"两个，其余（收藏、发现、文件传输助手、更多设置）一律不点。
- **通讯录列表**（x≈60–300）：
  - 顶部：搜索框 y≈20、「通讯录管理」按钮 y≈59；
  - 分组标题（可展开，右侧 x≈272 是数量）：公众号、服务号（33）、企业微信联系人（14）、联系人（22）；
  - 展开后的分组标题会吸顶（滚动时停在 y≈62）；
  - 联系人行高约 50，名字在 x≈133；字母索引在 x≈95；
  - 滚轮在列表上滚动有效，向上滚到顶能回到搜索框和「通讯录管理」。
- **资料卡**（点联系人行后显示在右侧，x≈430–800）：
  - 名字（大字）、`微信号：…`、`地区…`；
  - 朋友资料：`备注` / `添加备注名`（未设置时）；朋友圈；
  - 更多信息：`共同群聊 N个`、`来源 …`、`添加时间 YYYY-MM-DD`；
  - 识别时标签和值常被合并成一行（如"添加时间2023-06-08"），解析要按已知标签前缀拆分；
  - 底部「发消息」「语音聊天」「视频聊天」——**机器人禁止点这三个**。
- **「通讯录管理」**是一个**独立窗口**（720×560，标题"通讯录管理"）：
  - 左侧筛选：全部 / 朋友权限 / 标签 等；
  - 右侧表格，表头：名字、备注、标签、朋友权限；行高约 48，一屏约 10 行；
  - **表格里没有微信号**，微信号只在单个资料卡里有；
  - 关闭：窗口的标准关闭按钮（辅助功能里能找到 AXCloseButton，可按控件关闭，不用猜坐标）。

### 8.1 补充实测（同日稍后，同样只读、打码）

- **展开/收起分组**：点分组标题即切换（公众号 y≈113、企业微信联系人 y≈149，前一个分组收起时）。展开后标题右侧数量不再显示，下面是字母索引（x≈95）和行（行高≈50，名字 x≈133）。
- **公众号资料卡**：名字、`微信号…`（约 15 字符，形如 gh_…）、两行介绍文字、一个按钮（未点）。→ 公众号有微信号，可作强身份。
- **企业微信联系人资料卡**：名字（带 @企业 后缀）、第二行文字、`备注/添加备注名`、`朋友圈`、更多信息：`来源 企业微信`、`企业 …`、`视频号`、`实名 …`；底部 发消息/语音聊天/视频聊天。**没有微信号** → 弱身份（分类 + 名字 + 企业）。
- **「通讯录管理」表格**：一屏 10 行（y≈96 起，行距 48）；22 人约两屏，向下滚 3 格即到底。**文字识别会漏行**：一屏 10 行只认出 8 行（漏掉的两行名字可能很短或是表情）→ 同步必须按行的几何位置逐行处理，认不出名字的行单独标记，不能用"识别出几行"当人数。
- **标签筛选**：左侧「标签」展开后列出已有标签（本账号 2 个）；点某个标签，表格只显示带该标签的人 → 标签 = 逐个标签点开收集成员。
- **窗口意外关闭**：第一次连续滚动表格时「通讯录管理」窗口自己关了（原因未复现，第二次同样操作没关）→ 同步每一步都要确认窗口仍在，不在就重新打开并从断点继续。

## 9. 新的朋友（好友申请，2026-11-09，专用 Mac，只读）

探测方式：机器人已暂停；SSH 下 `wechat_click` 点击（该环境辅助功能已授权）、`screencapture -l <主窗口 id>` 截图、`wechat_ocr` 取坐标（返回 0–1 比例，原点左上，× 880/640 得窗口坐标）。昵称、验证消息不入记录。**坐标以 OCR 为准：视觉模型给出的像素坐标与实际偏差可达 200px，不能用来点击。**

- **发现**：左侧导航「通讯录」图标（30,169）右上角出现红色数字角标；进入通讯录后，列表第二行「新的朋友」（文字起点 x≈77、y≈113，在「通讯录管理」y≈59 之下、「公众号、服务号」之上）右侧也有红色数字。**打开一次申请详情后，两处红点都会消失**，之后申请仍在列表里，状态不变。
- **展开**：「新的朋友」是可展开的分组标题（箭头 〉→ V）。展开后申请直接列在它下面，不切换右侧页面：
  - 第 1 行 y≈160：昵称（x≈133）+ 右侧灰色状态文字 **「等待验证」**（x≈243，不是按钮）；
  - 第 2 行 y≈184：对方的验证消息（灰色小字，较长会截断）；
  - 展开后下面的分组整体下移约 105（公众号 y≈218、企业微信联系人 y≈254、联系人 y≈291）。
  - **Mac 版的「等待验证」表示"别人加我、我方未处理"**（与手机版含义不同）。
- **申请详情**（点昵称，点击区域避开右侧状态文字）：右侧显示昵称、验证消息、「回复」链接（x≈444,y≈203）、**来源**（本例：`通过搜索手机号添加`），以及按钮 **「前往验证」**（文字起点 x≈559、y≈328）。没有微信号、地区、添加时间。
- **「前往验证」弹窗**（2026-11-09，bot dry_run 诊断截图）：点击不直接提交，而是弹出独立窗口（360×640，与主窗口同 pid，layer 0，本例位于屏幕 (459,176)）。自上而下：标题「通过朋友验证」(y≈17)；「备注」(y≈66) 下为备注输入框（默认填申请人昵称，y≈103）；「标签」(y≈152) 下为占位文字「搜索或创建标签」(y≈190，本次 OCR 读成「搜奈或创建标签.」)；「朋友权限」(y≈248)，单选「聊天、朋友圈、微信运动等」(y≈286，默认)/「仅聊天」(y≈331)；「朋友圈和状态」(y≈378) 下两个开关「不让他（她）看」(y≈416)、「不看他（她）」(y≈460)；底部按钮「取消」(x≈97,y≈594)、「确定」(x≈233,y≈593)。
- **未观察**：点「确定」后的界面与状态文字（预期「已添加」，未实测）；弹窗用 Esc 是否关闭。

## 10. 语音消息与「转文字」（2026-11-09，专用 Mac，深色主题）

- **语音气泡**：对方（左侧）单行深灰气泡，高 37，宽随时长变化（3 秒 98、5 秒 116）。气泡内左侧是**喇叭图标**（喇叭口朝右），紧跟**时长数字 + 秒号**（`3"`、`5"`，单位秒）。Vision OCR 对整个气泡的实测读数：`")3"`、`•) 6"`、`•)) 5"`、`) 5"`、`•））ぶ"`（数字被读成假名）——图标读成括号/圆点，**不可依赖读出的字**。
- **未播放红点**：气泡右外侧红色小圆点。
- **「转文字」按钮**：未转换的语音右侧（红点之后）直接显示浅灰椭圆按钮「转文字」（本例窗口坐标中心约 x≈498–536，与气泡同一水平线）；**无需右键菜单**。
- **点击后**：按钮消失；语音气泡**正下方约 4–6pt** 出现一个新的左侧灰色气泡（左缘与语音对齐，±5pt；无头像、群聊中无昵称），内容是转写文字（例：「你好你好你好你好你好你好你好。」）。语音气泡本身像素不变。
- **对 bot 的影响**：转写气泡插在语音与其后消息之间（中间插入），未处理时连续性判为断档（2026-11-09 23:29 日志）。
