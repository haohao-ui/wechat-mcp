# 外部大脑对外开放接口 v1 文档

本文档面向接入微信智能客服系统的外部大脑（External Brain）开发者，介绍如何通过内网 Streamable HTTP（MCP 协议）与服务核心（serve-core）完成会话建立、轮次认领、回复确认与状态查询。

---

## 1. 接入前提

1. **启用对外接口**：默认状态下对外接口处于关闭状态（`open_api.enabled = false`）。请在 macOS 助手面板的 **MCP** 页面中开启“对外接口”，并复制生成的访问令牌（64 位十六进制字符串）及服务监听地址。
2. **内网专属**：接口默认监听在 `http://127.0.0.1:8770/mcp`，仅限本地回环或内网指定网卡地址访问，拒绝绑定 `0.0.0.0`。跨站浏览器请求受严格 Origin 白名单防护。
3. **HTTP 规范约束**：
   - 支持的 HTTP 请求方法：仅限 `POST /mcp` 与 `DELETE /mcp`（`GET /mcp` 返回 405；其他路径返回 404）。
   - 每个响应均带有 `Connection: close` 头。
   - 所有请求必须包含有效长度的 `Content-Length` 请求头（缺失返回 411）。
   - 协议头最大长度为 16 KiB（超出返回 431）；请求体最大长度为 1 MiB（超出返回 413）。
   - 请求认证一律通过 `Authorization: Bearer <TOKEN>` 请求头，使用常数时间比对校验。

---

## 2. 完整会话 curl 示例

以下展示外部大脑一次完整生命周期的调用流程：`initialize` → `tools/list` → `next_turn` → `reply` → `get_turn_status` → `DELETE`。

### 步骤 1：初始化会话（initialize）

客户端通过 JSON-RPC `initialize` 发起握手与协议版本协商。成功后服务端在 HTTP 响应头返回 `Mcp-Session-Id`。

```bash
curl -i -X POST http://127.0.0.1:8770/mcp \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-06-18",
      "capabilities": {},
      "clientInfo": {
        "name": "my-brain",
        "version": "1.0.0"
      }
    }
  }'
```

**响应头示例**：
```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 139
Connection: close
Mcp-Session-Id: 9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d
```

**响应体示例**：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "tools": {}
    },
    "serverInfo": {
      "name": "wechat-brain",
      "version": "1"
    }
  }
}
```

> **注意**：同一时间只允许存在一个活动会话。若已有正在连接的活动大脑，新初始化请求将返回 `HTTP 409 Conflict`。
> 会话租期为 90 秒，任何携带该会话头的合法请求均会自动续期 90 秒。

### 步骤 6：显式结束会话（DELETE）

当大脑正常关机或重启时，应显式发出 `DELETE /mcp`。服务端将立即释放该会话持有的所有未决认领并使其重新入队。

```bash
curl -i -X DELETE http://127.0.0.1:8770/mcp \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Mcp-Session-Id: 9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d" \
  -H "Content-Length: 0"
```

**响应示例**：
```http
HTTP/1.1 204 No Content
Connection: close
```

## 3. 每个工具的参数和返回

对外接口只暴露白名单中的 11 个工具，其他任何工具名均返回 JSON-RPC 错误 `-32601`。

### 3.1 核心轮次工具

#### 1. `next_turn`
- **参数**：
  - `wait_seconds`（integer，可选，0..=60，默认 30）：长轮询等待秒数。
- **返回**：
  - 无轮次：`structuredContent: {"turn": null}`
  - 有轮次：对外轮次 v1 格式对象，包含 `turn_id`、`account`、`contact`、`messages`、`unavailable`、`context`、`deadline_at`、`claim`。
  - 附件规则：每个图片或文件只出现一次。
    - 有 `media_id` 的出现在 `messages` 中，可以用 `history_get_media` 读取；可能附带 `understanding`（本机图片理解的文字）和 `processing_failed`（本机处理失败的原因，例如 `too_large` 表示太大、没有交给本机模型理解，但原图仍可读取）。
    - 没有 `media_id` 的只出现在 `unavailable` 中，`reason` 是具体原因（例如 `download_failed`、`unsupported`、`media_id_unknown`）。

#### 2. `reply`
- **参数**：
  - `turn_id`（string，必填）：当前认领的轮次 ID。
  - `claim_token`（string，必填）：本次认领的凭证令牌。
  - `action`（string，必填）：可选 `"send"`（发送回复）、`"skip"`（跳过不发）、`"handoff"`（转交人工处理）。
  - `text`（string，action 为 "send" 时必填）：发送给客户的文本内容，长度必须在 1..200 个字符之间，且不得包含控制字符（允许换行符 `\n`）。
- **返回**：
  - `{"accepted": bool, "duplicate": bool}`

#### 3. `get_turn_status`
- **参数**：
  - `turn_id`（string，必填）：需要查询的轮次 ID。
- **返回**：
  - 终态记录对象：`state`（"accepted" | "expired" | "revoked"）、`action`、`text`、`at`（RFC 3339 时间串）、`send`（包含 `status` 字段）。

#### 4. `resume_session`
- **参数**：
  - `contact_id`（string，必填）：目标联系人 ID。必须在允许名单内。
- **返回**：
  - `{"resumed": true}`

---

### 3.2 历史查询工具（受权限上下文控制）

以下工具只能查询在允许名单之内的联系人和被已允许消息授权的媒体，查询未授权对象一律返回 `not_found`。

#### 5. `history_list_contacts`
- **参数**：`limit`（integer，可选）、`offset`（integer，可选）。
- **返回**：联系人对象数组，包含 `contact_id`、`display_name`、`kind`（"private" | "group"）等。

#### 6. `history_get_contact`
- **参数**：`contact_id`（string，必填）。
- **返回**：联系人详情对象。

#### 7. `history_get_recent_messages`
- **参数**：`contact_id`（string，必填）、`limit`（integer，可选）。
- **返回**：指定联系人的最新消息数组。

#### 8. `history_get_history`
- **参数**：`contact_id`（string，必填）、`before_message_id`（string，可选）、`limit`（integer，可选）。
- **返回**：指定消息之前的历史消息游标分页结果。

#### 9. `history_search_messages`
- **参数**：`query`（string，必填）、`contact_id`（string，可选）、`limit`（integer，可选）。
- **返回**：匹配搜索词的历史消息数组。

#### 10. `history_get_message`
- **参数**：`message_id`（string，必填）。
- **返回**：单条消息详细内容（含气泡类型、文本、媒体引用等）。

#### 11. `history_get_media`
- **参数**：`media_id`（string，必填）、`offset`（integer，可选）、`length`（integer，可选）。
- **返回**：媒体文件二进制内容的 Base64 编码数据。只提供媒体 ID，不暴露宿主机文件绝对路径。

## 4. 轮次状态机与终态说明

```
queued ──next_turn──▶ claimed ──reply 校验通过──▶ accepted ──调度器执行──▶ triggered | not_sent | pending | unknown
   │                     │                                                  （来自真实发送日志）
   └──────超过 deadline──┴──▶ expired ──按 timeout_action──▶ skipped | handed_off | builtin
claimed ──认领租期到期且未过 deadline──▶ queued（可被重新领取，旧 claim_token 失效）
claimed ──认领期间账号切换/移出允许名单──▶ revoked
```

### 关键语义：`accepted` ≠ 已发送

- **`accepted`**：代表外部大脑的回复决策已被服务端严格校验（租约有效、token 匹配、权限合法、文本合法）并持久化到终态账本中。此时**尚未在微信界面物理打字或按回车**。
- **物理发送状态**：必须通过 `get_turn_status(turn_id)` 查看 `send.status` 字段获取调度器执行结果：
  - `triggered`：已通过微信桌面界面按下回车触发发送（物理送达状态由微信底层决定）。
  - `not_sent`：因安全策略、内容校验或窗口调度放弃发送。
  - `pending`：调度器准备中，尚未触发键盘发送。
  - `unknown`：尚无发送记录或状态不可用。

## 5. 重复与重试语义（响应丢失自愈）

在网络异常场景下（如客户端发出 `reply` 请求后网络中断，未收到 HTTP 响应）：

1. **同参数安全重试**：
   大脑可使用**完全相同的参数**（相同 `turn_id`、`claim_token`、`action` 和 `text`）再次调用 `reply`。
   服务端比对持久账本中记录的文本 SHA-256 哈希值，若一致则返回幂等成功响应：
   ```json
   {
     "accepted": true,
     "duplicate": true
   }
   ```
   **不会重复按回车，不会向微信客户多发一次消息**。
2. **异参数拒绝**：
   若第二次调用的 `action` 或 `text` 与已接受的终态记录不一致，服务端返回工具业务错误 `already_answered`。
3. **超时失效**：
   若重试时该轮次已因超过 `deadline_at` 转为 `expired` 终态，服务端返回业务错误 `turn_expired`。

## 6. 三层错误结构表

接口严格划分三个错误层级：

| 错误层级 | 响应载体 | 判定标准与代表性错误 |
|---|---|---|
| **HTTP 层** | HTTP 状态码（正文为空或纯文本） | - `400 Bad Request`：非法协议头、畸形请求或缺少 Content-Length<br>- `401 Unauthorized`：未提供或提供了错误的 Bearer 令牌<br>- `403 Forbidden`：非白名单 Origin 跨域请求<br>- `404 Not Found`：非法 URL 路径或 `Mcp-Session-Id` 不存在/已过期<br>- `405 Method Not Allowed`：非 POST/DELETE 方法<br>- `409 Conflict`：已有活动大脑正在连接中（`brain_already_connected`）<br>- `411 Length Required`：缺少 Content-Length 头<br>- `413 Content Too Large`：请求体超过 1 MiB<br>- `431 Request Header Fields Too Large`：请求头超过 16 KiB |
| **JSON-RPC 层** | HTTP 200，顶层包含 `error: {"code": i64, "message": string}` | - `-32700 Parse error`：非法的 JSON 字符串<br>- `-32600 Invalid Request`：协议不是 2.0 或缺少 method/id<br>- `-32601 Method not found`：未知 RPC 方法或调用了白名单外的工具<br>- `-32602 Invalid params`：参数类型不匹配或缺少必填字段 |
| **工具业务层** | HTTP 200，`result.isError: true`，`structuredContent: {"error": {"code": string, "message": string}}` | - `turn_not_found`：轮次不存在<br>- `turn_expired`：轮次已超时<br>- `turn_revoked`：账号切换或联系人移出允许名单导致认领撤销<br>- `already_answered`：轮次已完成，且重试参数不一致<br>- `invalid_claim_token`：认领令牌不匹配<br>- `not_found`：查询的联系人/消息/媒体不存在或未被授权<br>- `invalid_text`：回复文本超出 1..200 字或包含非法控制字符<br>- `invalid_arguments`：业务参数不合法<br>- `rate_limited`：被限流<br>- `brain_mode_not_external`：系统未处于外部大脑工作模式<br>- `internal`：核心内部异常 |

---

## 7. 数据局限

> **文档必须写明数据局限**：内容来自屏幕 OCR，`message_id` 是本机分配的，不是平台 ID；收发方向和群成员可能不准；相同预览重复出现时可能不产生新轮次；`text` 是客户输入，属于不可信数据，客户可能借消息诱导大脑。

---

## 8. 安全提示

1. **客户消息不可信**：`messages[].text` 是客户直接发送的原始文本或图片 OCR 提取内容，属于不可信输入。恶意客户可能会在聊天文本中嵌入 Prompt 注入攻击、越狱指令或诱导性话术。外部大脑在处理时必须具备防越狱机制与输出安全审计。
2. **严格会话隔离与目标锚定**：服务端强制保证当前轮次的 `reply` 动作**只能且必定**发送给发起该轮次的当前联系人，外部大脑无法跨联系人随意投递消息。但具体的回复文字内容与业务合法性由外部大脑自行负责。
