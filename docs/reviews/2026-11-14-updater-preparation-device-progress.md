# 生产更新：候选准备与专用机验证

本阶段完成真实候选准备，不等于安装或恢复完成。共享current_release记录v2方案仍等待Tech Lead确认；未修改该记录schema、journal schema或原启动守卫。

## 修改

- 新增prepare/private_fs/process：重新验签已下载封套与缓存receipt，要求规范UUID，通过目录FD读取私有缓存；复制固定归档并再次核对hash，使用原受控解包器拒绝未列出文件。
- 生产包必须包含10个bin程序和App宿主，共11个可执行组件及Info.plist。拒绝缺组件、意外可执行文件、不受支持的配置/角色/历史schema范围。
- 本机签名使用真实security/codesign，不开放沙箱mock或模拟故障入口。核对Mach-O架构、App标识、版本及序号；签名后要求全部程序的叶证书与当前安装App一致，并执行App深度严格验证。
- 系统命令采用固定绝对路径、有时限和输出上限，失败/超时回收本次进程组。失败清理仅限本次UUID暂存目录，不删除安装根。
- 新的apply --candidate <UUID> --dry-run只执行准备：会写私有缓存并解锁既有签名钥匙串，但不停止业务、不切换稳定入口、不写安装权威记录。没有dry-run的生产安装仍明确拒绝，待生产事务完成再启用；旧无candidate调用仍沿用原失败语义。
- 发布包在发布者签名前写入实际App版本/序号，并禁用tar的AppleDouble扩展。
- 宿主运行版本改读自身Bundle信息，开发散装程序显示“开发构建”；不再读取可滞后的VERSION文本作为运行版本。
