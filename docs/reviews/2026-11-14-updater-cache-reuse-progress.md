# 生产更新：缓存跨重启读回与复用

本阶段完成来源/下载链路中最后一项跨重启状态工作。没有完成整个生产安装与回退，也没有修改共享安装记录格式。

## 实现

- control update-status与wechat-updater status兼容增加download_cache。通过owner-only目录/文件、规范UUID、回执绑定、当前可信公钥、封套有效期和已有水位筛选可读缓存。
- 缓存状态明确为cached_not_revalidated：不扫描包体、不写文件，也不把历史回执当作当前摘要校验或安装证明。损坏、失效、撤销信任或不匹配的回执不展示。
- 页面重新打开后读取该兼容字段，核对当前已验签清单后显示“校验本地更新包”，没有仅凭缓存元数据显示“已下载并校验”。旧状态响应没有该字段时仍按原逻辑工作。
- 明确触发下载/复核时，在独占下载锁内重新获取并验签源清单，对匹配候选重新读取完整包体，核对精确大小和SHA-256；成功复用原UUID及回执，不重复下载或占用新缓存名额。
- 篡改缓存不能直接复用；有配额时重新下载有效源，保留原异常文件供检查，不擅自覆盖未知数据。旧独占锁、8个候选和1 GiB总量上限保留，配额预留涵盖封套及回执元数据。

- Swift更新UI集成目标通过，新增重启后不误报已校验、显示缓存待复核、仅显式操作才复核的断言。
