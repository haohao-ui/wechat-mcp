- 六页图及功能清单：`docs/design/current-pages-v1/README.md`。

- 更新最终图：`docs/design/planned-pages-v1/08-app-update-v2-simple.png`；旧更新图仅留档。

优先级：真实源码和已确认契约决定功能，当前用户决定展示简化，设计图决定视觉参考。图中示例数字、日志、角色、版本及状态不得进入生产默认数据。设计注释不作为产品模块。图中选中样式、导航宽度等不一致之处由 U1 统一。

不包含发布、部署、真实安装、远端运维、钥匙串操作、真实微信发送或付费模型调用。本计划不重复派发既有任务，不擅自解锁既有协调审查 gate。

## 4. 每项任务执行要求

### U0：先核对再实施

检查 HEAD、工作区、附属 worktree 和适用 AGENTS。保存用户未提交文档原样，不覆盖、不混入实现提交。核实旧任务可用提交、依赖顺序、改动归属和剩余阻塞；优先复用已有合适 worktree。若后续实际派发，按既有 Orca 协作约定选择隔离工作树。

产出 `docs/design/implementation-baseline-2026-11-14.md`，至少包含：八页入口/Controller/控制命令映射；逐项功能清单；只读与可写能力；所有按钮的启用条件；当前支持的最低系统；实际执行的检查、命令和结果。确定已有失败与未知项，不把历史955项通过当成本轮通过。

### U1：先统一外壳

统一浅深色语义色、系统字体、间距、细边框、圆角、选中导航和 SF Symbols 图标。导航顺序统一为总览、会话、联系人、大脑、MCP、设置、日志、应用更新。页面仅在对应真实 Controller 可用后注册；开发中不新增假的可用入口。

参考正文13–14pt、标题22pt、间距8/12/16/24pt、侧栏约196–216pt；依据真实窗口和内容调整，不机械按图片像素复制。沿用 AppKit，不引入新前端框架。共用组件限标题、分组、状态、消息反馈等实际复用部分。

main.swift 接线由一个集成人串行负责，只改页面注册与必要依赖注入，不改启动、信号处理、监督器和进程生命周期。Shell 注册方法等公共接口保持现状；如不足，先提交具体变更说明给 Tech Lead。

### U2：总览与会话

总览保留今日回复/监听会话/待人工、重新检查、全局暂停恢复及八类诊断，所有原有权限请求、重启确认和微信归位入口保留。无统计数据使用“—”，不展示示例统计或假正常状态。

会话只展示现有名称、状态/原因及转人工后的恢复按钮；不新增聊天记录、搜索、筛选、主动接管或发送入口。保留空态。全局恢复与单会话恢复不得混淆。状态刷新不得把失败解释为零数据。

### U3：联系人

保留初始化通讯录及影响确认、立即同步、刷新、同步完整性、待确认信息；五分类与计数；名字/备注、微信号、消息数、处理方式四列；详情中的微信号、备注、地区、添加时间、来源、企业/实名、标签、处理方式。

保留自动回复、忽略、取消忽略和公众号不可修改的条件逻辑。详情关闭/打开不挤成零宽；紧凑窗口允许详情切换展示，但不删列删字段。当前没有搜索能力，不因旧建议或图片外观顺便新增。失败回显与实际持久结果一致。

### U4：MCP 与设置

MCP 保留内置/外部模式、等待时限/超时动作/排队时限、保存反馈、接口启停、接口状态/URL、遮盖令牌/复制/重新生成及确认、接口测试、端点状态和另一处连接测试、两种接入示例与两种复制、工具分组列表。两处测试不得合并成语义不清的操作。大脑页只读连接摘要并跳转，本页继续唯一编辑模式和连接策略。

设置保留五项权限的状态/请求/系统设置入口及复查，四项只读账号模型信息，六项运行参数及原范围、窗口管理开关、配置说明、保存/恢复默认和反馈。恢复默认先填表，不立即写入。不得把只读账号、模型和密钥显示改成可编辑字段。

### U5：日志

保持三种来源、三种级别、关键词搜索、暂停/继续、清屏、只读日志、两个文件夹入口、复制诊断及反馈。清屏不得删文件；暂停日志不得暂停机器人。按当前实际日志语义展示，不生成示例生产日志，不顺带重写 tail 引擎。

### U6：大脑

优先复用既有 I3 实现，核对其六个 Tab 与设计图各区的一一对应；布局调整不得遗漏实际已实现的绑定、修订、初始化或恢复操作。图不能作为删除已有能力的依据。缺少既有契约的功能回原 owner，不在 UI 内复制状态存储或自行拼文件写入。

保留角色新增/编辑/复制/归档、角色定义、规则、知识导入/编辑/预览/启停、话术及变量/条件/频率、绑定、模拟测试、草稿保存、启用和历史回退（以复核后的既有实现/契约为准）。草稿与运行修订、加载失败、冲突、知识超限分别呈现。模拟只用合成数据，不操作微信；外部能力不支持隔离测试时禁用并解释原因。长表单可保留分区/Tab，不强行把全部内容挤进单屏。

### U7：应用更新简化版

默认只显示版本摘要、当前阶段说明和主按钮。有新版本时显示更新说明、发布时间与必要兼容条件；检查更新保留。移除常驻组件版本表、独立技术提示面板和多阶段并排示意，组件校验仍由原后端完成。

| 实际状态 | 显示与操作 |
|---|---|
| 未检查/检查中 | 当前版本；检查状态；避免重复提交 |
| 已是最新 | 当前版本和已是最新；允许重新检查 |
| 可更新 | 当前/可用版本、说明、时间、兼容要求；真实下载可用才启用下载 |
| 下载中 | 原按钮区显示进度；未知进度不用虚假百分比 |
| 已下载且校验通过 | 安装并重启、稍后安装；仅在原能力完整时启用 |
| 检查/下载/校验失败 | 原卡片内展示原因与适用重试；保留当前版本 |
| 激活后启动失败 | 仅原后端明确支持且存在兼容旧版本时显示恢复入口 |
| 未配置来源/信任根/当前不支持 | 如实说明；禁用不具备的动作，不能展示“已验证” |

旧记录中 I6 只读限制继续有效，除非已有后端能力经核实且相应 gate 已按原流程放行。UI 整理完成与完整更新功能完成是两个验收结果；后者未满足则 U7 为局部完成，U8 不宣称全目标通过。稍后操作只改变当前更新提示/延期状态，不能伪造已下载。

### U8：验证与交付

先按复核后实际构建入口编译，运行受影响的纯逻辑、Controller 适配和控制契约测试。状态映射、保存校验、操作范围、失败回退等补必要测试；不写只检查文案字符串的外观测试来代替真实布局。

八页各采集900×640、1180×800、1440×900pt的实际窗口或可靠离屏布局图，浅深色均检查，重点覆盖长中文名、长错误、联系人详情反复开关、大脑长表单、MCP JSON以及更新各真实可构造状态。不足宽高时使用内容滚动，主操作可到达；无重叠、非预期水平滚动或裁切。离屏截图只能证明布局，不能替代原生动态交互验收。

键盘Tab顺序、焦点、VoiceOver标签、减少动态效果、文字对比度列入检查。全量回归仅在测试隔离条件明确后执行，保留实际退出码和未完成项；禁止重跑至偶然通过、放松门禁或删用户资料。

报告包含精确基线/commit、文件、命令与结果、功能对照、截图索引、既有失败、新缺陷和未验证项。部署/真实微信/付费调用不包含在本计划测试中。按项目约定通过 Orca 报告实际任务交付，不把报告成功当作整个项目验收通过。

## 5. 实施顺序与文件协调

顺序为 U0 → U1 → U2 → U3 → U4 → U5 → U6 → U7 → U8。先以总览页确认统一视觉，再推广至其余页面。大脑/更新依赖未就绪不阻塞现有六页改版；依赖未完成时不得声称八页业务已全部可用。

后续若采用原有并行任务机制，U2/U3/U4/U5可在U1稳定后按文件归属拆开，公共组件和main.swift仍由一个owner串行集成；本次仅制定计划，不启动agent或Orca worker。已有任务worktree未核实前不创建重复任务。
