# 微信客服助手：桌面界面优化方案

日期：2026-11-14。范围：界面方案，不包含业务代码实施、部署、发送消息或项目验收。

## 设计依据

已检查当前 AppKit 源码：Shell、OverviewPage、SessionsPage、ContactsPage、McpPage、SettingsPage，以及 main.swift 页面注册；衔接现有 2026-11-10 大脑与应用更新规划。未启动应用进行视觉走查，因此以下是源码可证实的问题和设计建议，不将推测的显示问题当作真机结果。

ui-ux-pro-max 已执行 design-system 搜索及 SwiftUI 桌面表单建议搜索。采用其状态反馈、可访问性、稳定交互原则；不采用搜索返回的营销落地页结构、Lora/Raleway 字体及强制 OLED 深色。项目是中文原生桌面工作台，继续使用 AppKit 和系统字体，不为外观重写技术栈。

## 1. 核心方向

做一个安静、清楚、可接管的客服工作台。首屏依次回答：当前能否自动回复、哪里需要人工处理、下一步能做什么。

当前源码证据：

| 位置 | 现状 | 优化 |
|---|---|---|
| Shell.swift | 140–180pt 文字导航，无分组；初始视图 860×760 | 导航分组、统一图标、全局运行状态 |
| OverviewPage.swift | 三个指标和两个按钮同一横排；诊断逐项展开 | 标题操作区、独立指标、待处理事项、折叠健康明细 |
| OverviewPage.swift | 今日回复初始化为“-”，refreshData 未更新该值 | 未接数据时明确“暂无统计”，不显示虚构数字 |
| SessionsPage.swift | 纵向堆叠，姓名排序；姓名/状态固定 180/240pt | 可筛选列表，待人工优先，详情与执行状态分层 |
| ContactsPage.swift | 已有分类、表格、选择后详情和处理方式 | 保留基础，增加搜索和清晰的同步/自动回复反馈 |
| McpPage.swift | 模式、连接、工具集中；表单直接展示 timeout_action、skip 等 | 中文业务标签；角色与连接职责分开 |

## 2. 信息架构

侧栏建议宽 196–216pt，图标采用一致的 SF Symbols；名称始终可见。

```text
工作区
  总览
  会话          待人工数量
  联系人
配置
  大脑          依赖已有大脑规划实施
  连接与接口    现 MCP 页面
系统
  诊断与日志
  设置          含应用更新入口
底部：应用版本 / 当前运行状态
```

账号显示在主区顶部，首期单账号不做空的账号切换器。徽标只统计可处理的待人工事项，避免把普通日志数量当作报警。

## 3. 总览布局

```text
┌────────────┬──────────────────────────────────────────────────┐
│ 微信客服助手│ 总览                     [刷新] [暂停自动回复]   │
│            │ 当前账号 · 最近刷新时间                          │
│ 总览       ├──────────────────────────────────────────────────┤
│ 会话   3   │ 运行状态：自动回复运行中 · 当前角色：售前助手     │
│ 联系人     ├──────────────┬──────────────┬────────────────────┤
│            │ 今日回复     │ 监听会话     │ 待人工             │
│ 大脑       │ 暂无统计     │ 12           │ 3  查看待处理 →    │
│ 连接与接口 ├──────────────┴──────────────┴────────────────────┤
│            │ 需要处理                                         │
│ 诊断与日志 │ 张女士    模型超时       2分钟前  [查看会话]      │
│ 设置       │ 微信窗口  当前被遮挡              [查看原因]      │
│            ├──────────────────────────────────────────────────┤
│ v… · 运行中│ 系统健康  4项正常 / 1项待处理     [展开检查详情]   │
└────────────┴──────────────────────────────────────────────────┘
```

数字和角色为布局示例，不代表当前运行数据。优先显示影响自动回复的阻塞和人工任务；没有异常时显示简短正常状态，不用大量绿色诊断卡填满首页。

全局状态必须区分：运行中、已暂停、启动中、被阻塞、状态未知。数据读取失败时保留上次数据并标记“更新失败 / 上次成功时间”，不变成零。暂停发起后先显示“正在暂停”，后端确认后再改为“已暂停”；失败给出原因和重试。重启等低频操作放在诊断详情，保留现有影响说明与确认。

## 4. 会话工作区

采用列表＋详情结构。列表顶部搜索和分段筛选：全部、待人工、自动处理中、已暂停；待人工默认优先，同组按最近活动排序。先复用现有状态数据；最近活动等字段未接通时不伪造。

详情顶部显示联系人、自动回复状态、接管原因和操作；中间显示对话；侧边可展开本轮处理详情。只在有相应数据源时显示处理时间线：观察到消息 → 生成回复 → 发送触发 → 观察到己方回显。未知阶段明确“暂无记录”，回显不标成“已送达”。

当前会话页主要是监听状态和恢复按钮；完整对话、主动接管、执行时间线属于与现有对话闭环任务协作的新增能力，不能仅改布局就宣称完成。恢复按钮作用于当前会话，全局暂停作用于全部监听，文案明确作用范围。人工回复只有接入现有发送能力并验证后才开放。

空状态提供原因和入口：无联系人范围→前往联系人；筛选无结果→清除筛选；加载失败→重试。自动刷新保留选中项、滚动位置和正在阅读的历史位置。

## 5. 联系人

保留已有分类表格和选中后详情，不重建联系人模型。顶部统一为搜索、同步状态、同步按钮；明确区分“首次同步”和“更新联系人”，显示最近成功同步时间。同步期间解释其是否占用微信桌面，依据实际运行状态显示。

表格优先列为名字/备注、类型、处理方式；微信号和消息数可作为次要列或详情信息。自动回复开关明确保存中、成功、失败回退，失败不得留下已启用的视觉状态。批量操作等需求后置。

详情宽 280–320pt；宽窗口并列，窄窗口转独立详情或浮层，避免压缩所有列。保留源码中已有的“详情隐藏再显示宽度异常”防护，不直接换回旧的分栏实现。

## 6. 大脑、接口与设置

大脑页面承接已有规划：角色、业务规则、知识、通用话术、模拟测试；显著显示草稿与当前运行修订。底部操作为“保存草稿”“模拟测试”“启用”，各自反馈独立。没有后端版本/模拟支持前不开放这些操作。

连接与接口页面负责连接地址、凭据、连通性、超时策略和开发者工具。角色页只引用连接摘要并提供跳转，字段只有一处编辑来源。模式配置迁移须与现有任务统一，不同时在两页保存。

文案示例：

| 当前表达 | 建议 |
|---|---|
| 等待回复 (timeout_seconds) | 回复等待上限；单位放在输入框旁 |
| skip | 跳过本轮 |
| handoff | 转人工处理 |
| builtin | 使用内置大脑 |
| MCP | 连接与接口；MCP 保留在协议详情中 |

参数名、原始错误码、socket 路径放进可复制的技术详情。连接测试说明实际检查范围，通过不代表微信发送成功。令牌默认遮盖，复制后有明确反馈；重新生成说明旧连接受影响。

设置按“运行规则 / 权限与桌面 / 应用与更新”分组。字段附近显示单位、取值范围、错误。保存结果区分已保存和实际生效；按当前后端能力说明是否需要重启，不承诺未实现的热更新。更新显示应用版本、包说明、检查与安装状态，复用既定更新任务。

## 7. 视觉规范

| 项目 | 建议 |
|---|---|
| 风格 | 原生 macOS 工作台，低饱和中性色，少量绿色强调 |
| 字体 | 系统中文/系统字体；正文 13–14pt，页标题 22pt semibold，辅助 12pt |
| 数字 | 指标 26–28pt，等宽数字，附明确口径 |
| 间距 | 4/8/12/16/24/32pt；内容边距 24pt；分组间 24pt |
| 控件 | 常规按钮约 30–32pt 高；表格行 36–40pt；图标 16–18pt |
| 容器 | 8–10pt 圆角；细边框；只在浮层用明显阴影 |
| 动效 | 150–200ms 颜色/透明度反馈；遵循减少动态效果设置 |

颜色用 AppKit 语义色实现：windowBackgroundColor、controlBackgroundColor、labelColor、secondaryLabelColor、separatorColor、systemGreen/Orange/Red。品牌参考色为浅色 #15803D、深色 #4ADE80，实际文字/背景组合交付前测对比度；不把绿色用于全部按钮。正常/警告/错误同时使用图标和文字。

跟随系统浅深色。避免强制纯黑、霓虹光晕、大面积渐变和装饰性图表。设计尺寸建议默认约 1180×800pt，兼容约 900×640pt 的紧凑窗口，按可用屏幕大小调整；不直接将默认尺寸设为最小尺寸。低高度时只滚动内容，保留页面标题和主要操作。

## 8. 实施顺序与边界

1. **P0 基础与总览**：统一间距/标题/状态组件，侧栏分组，总览重排，移除无数据指标的误导，处理刷新失败与暂停中的状态。
2. **P1 日常操作**：会话列表筛选、联系人搜索、详情自适应、中文表单文案、行内校验与操作反馈。对话详情和时间线随对话闭环数据到位接入。
3. **P2 配置完整性**：大脑修订编辑/测试/启用，与现有连接页面分工，更新界面接入对应后端。

复用现有 ShellViewController 页面注册与控制命令。建议抽取 PageHeader、StatusBadge、InlineNotice、FormSection 等小组件，先由总览验证，再推广；不建立复杂组件框架。新增配置版本、历史接口或更新协议按已有任务契约处理，UI 方案不擅自修改公共接口和数据库。

主要落点：native/bootstrap/Shell.swift、OverviewPage.swift、SessionsPage.swift、ContactsPage.swift、McpPage.swift、SettingsPage.swift；大脑/更新页面随对应任务增加。用户已有的生产规划和任务书保持原样。

## 9. 实施验收

- 900×640、1180×800、1440×900pt 下无控件重叠、主操作截断或无意水平滚动；长中文名、长错误和详情反复开关均可用。
- 浅深色、键盘 Tab/焦点、VoiceOver 标签、减少动态效果逐项检查；正文对比度至少 4.5:1。
- 状态覆盖正常、暂停中、暂停失败、权限缺失、核心退出、读取超时、无数据；状态未知不展示正常。
- 刷新不跳列表、不丢选中、不覆盖未保存编辑；离开脏表单提示保存或放弃。
- 暂停/恢复作用域正确；配置保存与生效反馈符合真实后端；连接通过不展示为业务闭环成功。
- 有意义的逻辑测试覆盖状态映射、筛选排序、表单校验、失败回退；原生布局通过实际窗口与截图验收，不能用字符串测试替代。
- 本次仅新增方案文档，未修改 UI 代码，未运行应用或业务测试，不作真机视觉与功能通过结论。
