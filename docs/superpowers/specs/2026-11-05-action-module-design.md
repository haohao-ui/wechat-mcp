# 公共动作组件（Action Module）设计

日期：2026-11-05　分支：feat/wechat-bot-history

## 目的

RPA 的"手"：所有鼠标、键盘动作走同一个独立、可复用的组件，像真人一样操作——**过程随机，落点有效**。
现状是点击散落在 `native/bot/Files.swift`、`native/bot/Sessions.swift`、`native/bot/Worker.swift`、`native/wechat_click.swift` 等处，各自直接把光标瞬移到一点再按下/抬起，按下与抬起之间没有间隔。

## 成功标准（用户决定）

不是"命中某个精确像素"，而是**落在有效区域内即为成功**：
- 点击：按下与抬起的位置都在目标的有效区域内。
- 拖拽：被拖对象（或光标，视控件而定）落在放置区域内，且看到区域的接受反馈后才松开。

## 目标 / 非目标 / 反目标

- 目标：
  - 统一的动作接口：移动、单击、右键、双击、滚动、按键、粘贴、拖拽。
  - 拟人过程：轨迹、速度、手抖、停顿都带随机，每次不同。
  - 有效区域判定：落点不在有效区域就修正，修正不收敛就放弃并报错，绝不在区域外按下或松开。
  - 现有 5 处点击改用本组件（第一步）；拖拽为第二步。
- 非目标：识别目标位置（仍由现有截图/文字识别/界面元素逻辑给出区域）；回复节奏（回复延迟、打字时长、作息）另行设计，本组件只提供按键节奏的底层能力。
- 反目标：
  - 拟人化降低可靠性（点错、漏点、在错误位置松手）。
  - 用于绕过平台的人机验证（登录/安全校验滑块等）——遇到验证应停下通知人工，组件不提供这类用途。

## 取舍（设计者决定，可改）

- **可靠与统一优先，拟人为中等强度**：默认参数下单次点击约 0.3–0.8 秒；另有 `instant` 模式（不移动轨迹、仍校验区域）用于测试和排障。

## 输入：目标区域

调用方传入的是区域，不是点：
- `rect`：控件的完整矩形（屏幕坐标，单位为"点"，非像素；Retina 下截图像素需先 ÷ scale）。
- `inset`：有效区域内缩比例，默认四边各 20%，小目标（宽或高 < 16 点）内缩改为 2 点，避免有效区域过小或为空。
- 可选 `precise`：菜单项等密集小目标，降低抖动幅度与落点离散度。

## 算法：带噪声的终点逼近

1. **落点采样**：在有效区域内取截断二维高斯（中心为区域中心，σ 为区域半宽的 1/3），沿移动方向加一个小的"未到"偏置（人常略停在近侧）。
2. **用时**：费茨定律 T = a + b·log₂(D/W + 1)，乘对数正态随机系数；D 为距离，W 为目标在移动方向上的宽度。
3. **路径**：三次贝塞尔曲线，两个控制点在起终点连线的垂直方向随机偏移，偏移量 ∝ 距离（手腕弧线）。
4. **速度**：进度 s(t) 用最小加加速度曲线 10t³−15t⁴+6t⁵，再做时间扭曲使速度峰值前移到约 35–40%（前快后慢）。
5. **手抖**：生理震颤（8–12Hz，0.3–1 点）+ 低频漂移，二者乘包络 (1−s)²，越接近终点越小。
6. **主移动误差**：主移动的实际终点 = 采样落点 + 误差，误差标准差 ∝ 距离（远则偏得多）。
7. **有效区域判定**：
   - 终点在有效区域内 → 直接点击，不再修正。
   - 在区域外 → 做一次短而慢的修正移动（误差缩小到约 30%），重复判定。
   - 修正次数上限 3 次；仍不在区域内 → 不按下，报 `target_not_reached`。
   - 由此，小目标自然修正更多、大目标多数一次到位，无需单独设定"修正概率"。
8. **点击**：到位后停留 50–150ms，按下 60–120ms 后抬起；按下与抬起之间如有微移，仍须在有效区域内。
9. **事件发送**：以 60–120Hz 发出，时间间隔带小幅抖动；位置限制在当前屏幕范围内。

## 拖拽（第二步）

阶段：靠近 → 按下停 80–200ms → 慢速越过拖拽阈值（3–6 点）→ 主搬运（发 `leftMouseDragged` 而非 `mouseMoved`，可有一次 20–60ms 微停顿）→ 在放置区上方悬停 150–300ms（保留极小抖动，等待高亮）→ 判定后松开。

- 判定依据：被拖对象或光标在放置区域内（需要时用截图/界面元素读取对象实际位置，处理"抓取偏移"和非 1:1 跟随）＋看到接受反馈。
- 不收敛：按 Esc 取消拖拽（或拖回起点松开），报 `drag_not_converged`，绝不在区域外松开。
- 路径避开列表/窗口边缘的自动滚动带。

## 人机抢鼠标检测

每次发送事件前读取当前光标位置，与上一次自己发出的位置偏差超过阈值（例如 3 点）即视为有人在操作：立即中止（拖拽中则取消），报 `user_input_detected`，不再继续本动作。

## 结构

```
native/action/
  Trajectory.swift  纯计算：起点、目标区域、参数、随机种子 → [(t, x, y, phase)]；不访问系统
  Executor.swift    按时间戳发送系统事件；每步做抢鼠标检测；按下/抬起前做有效区域判定
  Actions.swift     move / click / rightClick / doubleClick / scroll / key / paste / drag
  Profile.swift     参数集（速度、抖动、离散度、修正上限）；内置 default、precise、instant
```

- 远端为 Swift 5.7（macOS 12），不用 5.9+ 语法。
- 随机数可注入种子，测试可复现；生产用系统随机。
- worker 与 `wechat_click` 都编译进同一份源文件。

## 迁移（第一步）

现有点击位置改为调用 `Actions.click(region:)`：会话列表点击、标题区域、右键"另存为"、输入框聚焦、`wechat_click` 命令。每处给出控件的矩形（现有代码已有点坐标的，按控件已知尺寸给矩形）。行为验收：现有测试全部通过；真机跑一轮文字、图片、PDF 回复和一次 `send_file`。

## 验收

1. 轨迹属性测试（固定种子、成千上万次采样）：
   - 起点正确；按下与抬起点 100% 在有效区域内（或报错，不按下）。
   - 速度峰值位于前半段。
   - 用时落在费茨定律给出的范围内。
   - 手抖幅度有上限，包络在终点为 0。
   - 所有点不出屏幕；修正次数 ≤ 3。
   - 小目标的平均修正次数高于大目标。
2. 拖拽（第二步）：中间阶段全为拖动事件；不收敛时不发松开事件。
3. 抢鼠标：模拟光标被外部移动 → 中止并报 `user_input_detected`。
4. 真机：迁移后机器人行为不变；记录每次点击平均用时。

## 留给实现者

费茨定律常数 a、b 的具体取值（以真机测量的人手数据为参考范围）；低频漂移的具体噪声实现；滚动的加速与惯性曲线；按键节奏的分布。

## 风险

- 每次点击变慢 0.3–0.8 秒，机器人每轮处理时间增加。
- 拟人移动经过的位置会触发悬停效果（提示框、高亮），可能遮挡后续截图；必要时动作后把光标移到安全空白区。
- 抢鼠标检测阈值过小会误报（系统光标加速度/取整），需真机校准。
