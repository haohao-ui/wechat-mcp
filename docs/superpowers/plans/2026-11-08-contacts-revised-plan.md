- 外部大脑仅访问允许名单内数据；忽略名单优先。以上边界的完整端到端复审不在本次完成范围内。

## 3. 已发现的逻辑问题

### P1-A：先同步、后启用自动回复仍可能生成重复联系人

证据：`HistoryStore::ensure_contact`（store.rs:488–536）只查 `config/alias` 名字；通讯录新建的名字来源是 `addressbook`。联系人页启用自动回复仅把名字写入允许名单（ContactsPage.swift:216–264、724 起），下一轮 scheduler.rs:1393 起调用 ensure_contact。

触发：同步创建联系人 A → 在联系人页勾选 A 自动回复 → 没有 config/alias 所有者 → 新建 B。d555a68 保证来源不降级，但没有覆盖此顺序。

修复目标：复用唯一且类别相符的通讯录身份；遇到多个候选则明确待确认，不能简单取第一条或把所有来源无条件合并。保持群聊/私聊的身份边界。

### P1-B：增量同步按名字命中第一条，可能跳过真正需要读取的资料

证据：sync.rs:254 读取账号全部 profile；:614–625 以 nickname/remark 的 `.find()` 命中后跳过资料卡，没有限制 category、检查候选唯一性或 removed_at。

后果：个人联系人和企微同名时可能把前者计入后者；同名不同企业可能折叠为同一 cid；已移除联系人重新出现时仅计数，不清 removed_at。名字没变、其他资料变了也不会刷新。

修复目标：分类内唯一且当前有效的候选才允许快捷路径；重名/弱身份不确定时打开资料卡。重新出现需要清除移除标记。另设周期全量资料刷新或明确刷新策略，不能声称名字增量能发现所有资料变化。

### P1-C：扫描失败或不完整也会标记联系人移除

证据：sync.rs:269–275 只判断 `!r.stopped` 就执行 mark_missing；人数不足、OCR 未读、NeedsReview 均不阻止这一步。之后才计算不完整状态。

后果：OCR 漏读一行或身份冲突就可能把仍存在的联系人标记移除。此操作不删聊天，但会污染联系人状态。mark_missing 的数据库错误还被忽略。

修复目标：只有分类扫描覆盖完整、无未读/待确认、身份唯一且人数一致时才提交移除；失败扫描可保留已确认的新增/更新，但不能得出删除结论。数据库错误必须反映为失败。

### P1-D：换账号后沿用原账号允许名单

证据：scheduler.rs:468 起替换数据 account_id，但 rules 沿用配置 allowlist；match_entry/decision 按名字判断。ContactsPage.applyHandling 也只按名字写全局配置。

后果：B 账号存在和 A 相同的会话名字时可能继承 A 的自动回复授权。现有标题检查只能证明会话名字一致，不能证明跨账号授权一致。

修复目标：先在账号未确认、检测冲突或换号时停止自动回复；按账号加载处理规则。账号范围配置属于公共契约变更，应单独出兼容方案再实施，不能在本轮擅自改 schema。旧规则仅绑定经确认的原账号，不复制到新账号。

### P2-A：同步结果和每日尝试时间没有账号范围

证据：scheduler.rs:1662 起、1766 起与 sync.rs:122–158 使用 state 根目录固定文件，结果中未附账号；control.rs:1434 起过滤联系人账号，却直接加载同一同步结果。

后果：换号可显示前一账号的成功数量，并因其 20 小时记录延迟新账号同步。

修复目标：同步请求、结果、最近成功、最近尝试均绑定账号；查询验证归属。每日失败状态和上次成功时间独立保存，保留限流，避免失败覆盖成功证据。

### P2-B：名单别名丢失判断已撤回

进一步追踪 `ConfigFormLogic.buildUpdatedConfig → parseContactEntries` 后确认：同名同类型的原条目会被合并恢复，aliases 不会仅因界面重建 recipient/kind 行就丢失。此前检查停在调用方，判断不完整；不据此修改代码。

### P2-C：资料写入不是单一事务

证据：store.rs:1345 起用互斥锁串行化，但 update/insert 联系人、profile、名字执行多个独立 SQL，没有数据库事务。

风险：后续 SQL 失败时留下部分更新；锁不等于断电或 I/O 失败时的原子性。

修复目标：一次 profile upsert（含名字登记）在事务内提交；失败不产生孤立联系人。不要扩大到整体存储重写。

### P2-D：原计划 UI 缺口仍存在

- ContactsPage 列只有名字/微信号/消息数/处理方式；缺最近对话列、详情历史入口。
- SessionsPage 缺分类、最近回复时间。
- SettingsPage 密钥只有状态，没有设置入口。
- LogsPage 有实时日志，但缺重要事件视图。
- 缺扫描微信界面/校准的宿主入口；补按钮前还须核验当前 control → scheduler → worker → candidate/active 布局链，不能只做显示成功的按钮。

这些按源码确认，未逐按钮实机验收。待确认事项应通过实际功能入口闭环，不能只展示一张提示列表。

## 4. 新开发顺序与验收

### 阶段 1：联系人身份与配置保存（先做）

文件：history/store.rs、scheduler.rs、ContactsPage.swift 及对应测试。

- 覆盖两个登记顺序：先允许后同步、先同步后允许；启用后、重启后 cid 和消息关联不变。
- 唯一通讯录候选复用；同名多候选拒绝静默绑定；同名群聊/私聊不能共用身份。
- 修改一人处理方式不丢其他人 aliases；忽略优先和取消忽略行为保持一致。
- profile 写入原子化；注入中途失败时 contacts/profile/names 均无部分提交。
- 不按真实名字做分支，不自动合并已有重复数据。

### 阶段 2：同步覆盖与移除判定

文件：contacts/sync.rs、parse.rs（仅在有证据需要时）、scheduler.rs。

- 跨分类同名、同分类重名不同企业、移除后重现都进入正确路径。
- 缺一行、OCR 失败、待确认、分组缺失、停止、滚动上限均不能误报完整或标记移除。
- 只有确认完整的分类才提交移除；报表区分 expected、已确认唯一身份、未读、待确认、错误。
- 完整同步重复运行幂等；第二屏开始的顺序、字母行、部分可见行有合成场景覆盖。
- 核验离开通讯录失败、租约释放失败和暂停恢复是否有可见错误，避免吞错后宣称成功。
- 明确“新增/改名检测”和“已有资料刷新”两种能力；先保证正确，再优化点击次数。

### 阶段 3：账号切换完整隔离

文件：wechat_account.rs、serve.rs、scheduler.rs、control.rs、配置及宿主设置相关模块。

- 先制定账号规则保存格式、旧配置迁移和回退方案；涉及公共配置变更的部分由负责人确认后实施。
- A→B→A 数据保留，各号同步状态、每日调度、允许/忽略规则互不继承。
- 账号识别 None、多个候选、检测延迟时停止产生有副作用的操作，界面明确等待确认。
- 检查“首次清空”历史兼容逻辑，生产迁移不再次套用旧测试数据清空授权。
- 加账号切换集成场景，不能只测试 account_id 字段过滤。

### 阶段 4：校准与待确认闭环

- 先核对实际布局候选生成、差异展示、接受、备份、激活和失败回退，再接宿主按钮。
- 无需改动名字规则来掩盖布局错位；没有匹配布局时给出明确阻断原因。
- 企业微信同名保留两条并显示企业辅助辨认；实际确认重复后才走显式合并流程。
- 待确认项提供查看证据和处理入口；如需新增命令/接口，先列契约及测试再实施。

### 阶段 5：补齐剩余界面

## 6. 本轮已实施修复（工作区，尚未部署）

- `history/store.rs`：通讯录先建档再加入允许名单时复用唯一有效身份；群聊/私聊分开。资料关联也限制会话类型和已有资料分类。profile、contact、名字登记使用同一事务，失败整体回滚。
- `contacts/sync.rs`：增量快捷路径要求当前账号数据、分类一致、精确且唯一的有效强身份；屏内重名、弱身份、已移除记录重新读卡。完整且无未读/待确认的分类才可标记移除。
- `scheduler.rs`、`serve.rs`：生产账号检测器在同步前和采集中复核登录账号；换号/退出即中断，卡片读取后再次检查，禁止将该卡写入旧号。旧无账号断点不再自动触发同步。
- 同步请求附账号，拒绝不属于调度器账号的请求；结果、最近成功、每日尝试按账号摘要分文件保存。固定响应文件仅供请求 ID 与账号双重核验，不作为每日调度或联系人页的跨账号状态源。
- `control.rs`：联系人页读取当前账号结果；等待同步时同时校验请求 ID 和账号。
- 没有新增针对具体联系人、微信号、企业、电脑或联系人数量的生产分支；沿用已有每日同步时段和间隔。

实际验证：同步 47、历史 110、调度 109、控制命令 48、serve 10 项测试通过。新增覆盖先同步后启用、群聊/私聊同名、企微同名不同企业、不同登录账号、重现联系人、不完整扫描保留状态、读卡中途换号、事务回滚和账号调度记录隔离。`git diff --check` 通过。

边界：未连接实机、未部署、未提交/推送，未做全量发布验收。增量的免读卡路径不能发现“名字完全未变但其他资料改变”，该情况仍需全量刷新。账号范围的允许/忽略规则配置（P1-D）及剩余界面任务尚未实施；本次账号隔离限定于同步及其数据/状态，不宣称自动回复规则已完成账号隔离。
