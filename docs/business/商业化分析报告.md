## 0. 执行摘要

### 0.1 三句话结论

1. **需求是真的。** 微信私域电商 2025 年交易额 6.4 万亿元（+28%）、企业级智能客服市场 71.9 亿元（+55.3%）、全国个体工商户 1.27 亿户；企业微信官方通道覆盖不到"个人号存量好友"，这是真实存在、且长期未被合规产品满足的长尾缺口。
2. **产品是能打的。** 这不是 Demo：51 个 MCP 工具、1,104 个测试用例、7 项可验证的技术差异化（应用无关的 macOS 眼手、轮次编排、幂等发送、本地历史、外部大脑协议等），最小可信内核已在专用 Mac 上跑通真实收发；真实模型自动回复在 Python 版上验收过，迁到 Rust 后尚未复验。
3. **合规是硬墙。** 微信安全中心 2026-01-29 公告已把"截图 + 辅助服务读取 + 模拟按键 + 自动回复 + 管理聊天记录"逐项列为违规；腾讯软件许可协议把授权限定为"非商业目的"；AI 标识、个人信息、数据出境三条红色风险叠加。**卖"个人微信自动化"这件事本身在平台规则层面就是确定违规**，与"只回复白名单""只操作自己账号"无关。

所以真正的问题不是"能不能赚钱"，而是"**愿意以什么法律地位、承担多大风险、做多大规模**"。

### 0.3 核心建议：换一个品类卖

**不要把产品定义为"微信机器人"，要定义为"macOS 桌面 Agent 引擎"。**

| 组合 | 内容 | 定位 |
|---|---|---|
| **主线（12 个月）** | 把通用眼手底座（`desktop_*` + 拟人动作 + MCP 协议）产品化为 **Mac 桌面 Agent 引擎**，向 AI Agent 厂商 / RPA 厂商 / 垂直 SaaS 做**技术授权与白标** | 通用工具，法律定性风险最低，TAM 最大 |
| **辅线（0–6 个月）** | 对医美/教培/保险等**邀请制设计伙伴**做私有化交付（19,800 元/首年），收现金流与反馈 | 不公开营销、不做 SaaS、不承诺防封 |
| **不做** | 公开售卖"微信自动回复工具"、SaaS 托管代运营、多开/群控/协议/Hook、任何"防封/规避检测"功能 | 刑事与平台风险最高、品牌不可逆 |
| **备选（12 个月后）** | 企业微信 / 公众号官方 API 的 AI 客服 | 合规但红海，需重新定位 |

**为什么换品类而不是换功能？**

- **法律定性首先看"是不是专门用于微信"**。同一套代码，作为"通用 macOS 桌面自动化引擎"与作为"微信自动回复外挂"，在刑法 285 条 3 款下的风险等级相差一个量级；影刀 RPA 公开支持操作微信并售卖 5,988 元/账号/年，而"定制 V/微信外挂"已有实刑判例——差别不在技术，在**产品定位与功能清单**。
- **代码资产 80% 可复用**：`desktop_apps/windows/observe/act`、AX+OCR 双源观察、拟人轨迹、单次观察凭证、幂等发送、MCP 双入口，本来就是应用无关的；微信只是其中一个应用模板。
- **微信场景不放弃，但降级为"内部标杆 + 邀请制交付"**：既能维持现金流，又不把品牌和公司命运押在一个确定违规的叙事上。

## 1. 分析对象与方法

### 1.1 这个项目实际上是什么

README 仍以"个人微信 RPA / MCP 服务"呈现，但代码已经演进成一个**四形态产品**：

```text
① stdio MCP 服务      51 个工具，给 Claude Code / Codex / Cursor 等 Agent 用
② Swift GUI 宿主      「微信客服助手」6 页 App，解决 TCC 权限与常驻（launchd）
③ 常驻 Rust Core      serve-core：调度、轮次、白名单、历史、通讯录、好友申请、备份
④ 外部大脑 Open API   内网 HTTP MCP（11 工具），把"接待轮次"租给任意外部模型/Agent
```

技术栈的独特之处：**不碰协议、不注入进程、不解密数据库**，只通过 macOS 辅助功能 + 屏幕截图 + Vision OCR + 模拟键鼠操作可见界面。这既是它相对 Hook/协议方案更安全的地方，也是它被平台规则"逐项点名"的原因。

### 1.2 方法与证据

| 证据类型 | 来源 | 用途 |
|---|---|---|
| 代码与文档 | 仓库 HEAD + `docs/` + `research/*acceptance*` | 盘点真实能力与成熟度 |
| 本机实测 | `tools/list`、`tools/call`、`cargo fmt/clippy/test` | 验证契约与门禁 |
| 二手市场数据 | IDC、网经社、市场监管总局、企查查类公开报道 | 市场规模与价格锚点 |
| 法规与判例 | 微信官方规范/公告、刑法与司法解释、公开判决 | 合规定性 |
| 财务建模 | 本报告自建三情景模型 | 收入/成本/盈亏平衡 |

### 1.3 局限

- **未做客户访谈**：所有付费意愿判断来自价格锚点与行业成本推导，不是真实成交数据。
- **封号概率无公开统计**：报告中的概率是专家估计，只能用于排序，不能用于定价精算。
- **竞品真实成交价未知**：挂牌价与招标价差 1–2 个数量级，本报告只用挂牌价做价格带参照。
- **未做法律意见书**：合规结论是尽调级判断，商业化前需专业律师出具正式意见。

## 2. 产品与资产盘点

### 2.1 能力全景

| 模块 | 能力 | 成熟度 |
|---|---|---|
| 微信收发（统一工具） | 会话列表、读当前会话、发送文本/文件、等待消息 | **已实机**（单账号、单联系人） |
| 白名单自动回复 Bot | 多私聊白名单 + 排除、轮次聚合（静默 10s/上限 60s）、限流（15s/20 次每小时）、图片/文件理解、人工已回复拦截、暂停/恢复 | Rust 版**仅自动化测试**；Python 版有 3 条真实模型+发送记录（代码已删） |
| 历史库 | 可见消息、附件 SHA-256、FTS5 检索、媒体理解要点、别名/合并、备份/恢复 | 仅自动化测试 |
| 通讯录同步 | 分组截图识别 + 翻页 + checkpoint 续传 | 仅自动化测试 |
| 好友申请 | 规则匹配、dry_run、OCR 定位点击、去重、限额 | **未验收**（验证对话框无真机证据，默认关闭） |
| 外部大脑 Open API | 轮次认领/回复/终态账本、11 工具、令牌与 Origin 白名单、单会话租约 | 局部实机联调，无正式验收 |
| 通用眼手 | 应用无关：列窗口、AX+OCR 观察、focus/click/drag/scroll/key/type、拟人轨迹 | **实机 blocked**（遮挡判定问题） |
| 公众号文章 | 公开网页 → Markdown + 图片 | 仅自动化测试 |
| 宿主 App | 6 页 UI、权限、socket、core 监护、状态面板 | 旧宿主已实机，新面板未验收 |

运行时实测：**51 个工具**，其中 5 个通用桌面工具、7 个历史工具、3 个外部大脑工具；`outputSchema` 为 0，错误只有自然语言文本。测试实测：`cargo test` 1,104 例（1,089 pass / 15 fail / 1 ignored），`fmt` 与 `clippy` 已恢复绿色。

### 2.2 成熟度分级（关键结论）

**已实机验收的最小可信内核**：单账号私聊的 OCR 读取 + 核验式发送 + 幂等记录 + 轮次聚合 + 亮暗主题 880×640 自适应 + 操作浮层。

**仅自动化测试**：Rust Bot core、历史库、通讯录、Open API、备份恢复、语音转写、6 页宿主 App。

**未完成/未验收**：`history_*` 工具（列而不可调）、通用眼手（实机 blocked）、好友申请、群聊自动回复、多账号/多平台、语音回复。

> 这意味着一句很重要的话：**"能演示"和"能签合同"之间，还隔着一次完整的 Rust 版实机复验。** 现有最有力的验收记录（真实模型 + 真实发送）属于已删除的 Python 实现，不能直接继承。

### 2.3 七项技术差异化

| # | 差异化 | 为什么值钱 |
|---|---|---|
| D1 | **应用无关的 macOS 眼手** | AX + OCR 双源、单次观察凭证、动作前重新核对 PID/窗口/几何、OCR 局部像素校验、拟人轨迹（贝塞尔+费茨+抖动）；可扩到任意 Mac 客户端，不止微信 |
| D2 | **双入口 Agent 协议** | stdio MCP（51 工具）+ 内网 HTTP MCP（11 工具）；`next_turn→reply→get_turn_status` 带租约、claim_token、终态账本、同参重放幂等 |
| D3 | **轮次编排与视觉连续性** | 静默聚批、双帧一致、锚点、重复计数、`gap/ambiguous` 只跳过不猜、人工已回复三源拦截、phash 图片去重、滚动拼接、发送后回显复核 |
| D4 | **本地优先数据底座** | SQLite WAL + FTS5 + 内容寻址附件 + 备份 manifest/sha256 + restore；客户数据不出机 |
| D5 | **可复现测试资产** | 1,104 用例、FakeWorker/FakeMcpServer、故障注入、frame dump + 离线 replay |
| D6 | **面向非技术商家的最后一公里** | GUI 宿主 + launchd 自愈 + 一键安装 + 自动注册 8 类 Agent + 系统权限引导 |
| D7 | **本地模型/本地执行** | codex-exec 或 OpenAI 兼容（可接 DeepSeek），密钥 0600，不要求自建推理集群 |

**判断**：真正的护城河是 **D1 + D3 + D5**——在"不稳定的可见 UI"上做到"少误发、少漏回、可复现"。模型不是护城河，微信 UI 适配 know-how 和可靠性工程才是。

## 3. 市场分析

### 3.1 需求从哪里来

个人微信 AI 客服的付费动机，本质是三个可量化的损失：

1. **响应时差损失**：客户深夜/周末发来咨询，无人回复 → 线索冷却。医美/教培的线索成本已达 250–12,000 元/人，漏一条就是真金白银。
2. **人力成本**：私域运营岗 6,000–14,999 元/月，客服外包共享坐席 600 元/月起、品牌专席 9,000 元/月；一个小商家养 1 个客服的年成本 7.2–18 万元。
3. **重复劳动**：报价、地址、营业时间、预约、资料发送——高频、低创造性、可被 AI 接管。

而企业微信官方通道**解决不了"个人号存量好友"**：客户已经加在个人微信上，迁移到企微需要重新加好友、重新建立信任，转化损失远大于工具成本。这就是长尾缺口的来源。

### 3.2 市场规模：可信锚点与不可信数字

| 口径 | 2025 年量级 | 可信度 | 与本项目关系 |
|---|---|---|---|
| 私域电商 GMV | **6.4 万亿元**（+28%），用户 6.8 亿 | ✅ 网经社 | 需求侧的"钱"，不是软件市场 |
| 企业级智能客服 | **71.9 亿元**（+55.3%） | ✅ IDC / 财联社 | AI 客服的直接可比市场 |
| 私域运营解决方案 | **137 亿元** → 2030E 253 亿元 | ⚠️ 均识咨询，二手 | 最贴近的天花板 |
| 企微 SCRM | 「180 亿 / 255 亿」 | ❌ 仅见内容农场，**禁止引用** | 竞品池，但数字不可信 |
| 个人微信自动化 | **无公开统计** | — | 实际赛道，只能估算 |

**自下而上估算**（推断，非事实）：

```
可服务市场 ≈ 1.27 亿个体工商户 × 0.3%（有私域需求且愿付费）× 1,000–3,000 元/年
          ≈ 38–114 亿元/年（理论上限）
```

再乘"macOS + 个人号 + 愿承担封号风险"三重筛选，真实 SAM 会掉到**千万到亿元级**。这个量级足以容纳一个 1–5 人的精品团队，但不足以支撑 VC 叙事。

### 3.3 客群与 ICP

| 客群 | 付费意愿 | 依据 | 风险 |
|---|---|---|---|
| **医美/口腔/植发** | ★★★★★ | 获客成本 8,000–12,000 元/人；一次成交覆盖工具年费 | 医疗广告/资质敏感，AI 话术易踩线 |

| **本地生活/连锁** | ★★★ | 高频、价格敏感 | 需要标准化产品，定制成本高 |

### 3.4 定价锚点

| 锚点 | 价格 | 对本项目的含义 |
|---|---|---|
| 私域运营岗 | 6,000–14,999 元/月（含社保 7.2–18 万/年） | 工具定价 1,999–3,999/年 = 人力成本的 1%–5%，决策几乎不需要 ROI 论证 |
| 客服外包共享坐席 | 600 元/月起 | 低价替代，但需要客户自己管人 |
| 企微 SCRM 轻量版 | 99–330 元/账号/年 | 合规低价锚，不能硬碰 |
| 企微 SCRM 标准版 | 840–1,080 元/账号/年 | 中端锚点 |
| 企微 SCRM 项目制 | 8 万元/年起 | 大客户锚点，本项目短期够不到 |

| Wechaty + PadLocal | ≈2,400 元/年/号 | 开源方案的成本锚 |

**结论**：本项目的合理价格带是 **1,999–3,999 元/年（软件）+ 19,800 元/首年（私有化）**，显著低于影刀、高于 Wechaty 的协议成本，用"AI 原生 + 免开发 + 本地数据"解释溢价。

### 4.3 本项目的真实位置

**优势**：
- 唯一同时具备"AI 原生 + 本地执行 + 受控白名单 + 可审计"的方案；
- 通用眼手可跨应用，天花板高于单一微信场景；
- 工程可靠性（幂等、互斥、轮次、回放）明显强于开源与灰产方案；
- 数据不出机，对医美/金融等敏感行业有吸引力。

**劣势**：
- macOS-only、单账号、专用机，TAM 被砍到 1/10；
- 无群聊、无多账号、无知识库/订单系统、无官方回执；
- 未签名分发、仓库私有、安装摩擦大；
- 品牌与 README 仍绑定"微信"，法律上处于最不利的叙事位置。

**机会**：
- 企微 5.0 内置免费 AI 会吃掉"标准客服"，但吃不掉"个人号长尾 + 本地数据"；
- MCP/Agent 生态爆发，开发者对"可靠的 Mac 眼手"有真实需求；
- 微信对协议类打击越来越严，纯 UI 路线的相对安全性反而上升（但仍违规）。

**威胁**：
- 平台规则持续收紧（2025-07、2026-01 两次公告）；
- 大厂 computer-use 能力商品化；
- 微信版本升级导致 UI 适配失效；
- 封号事件引发的口碑与退款连锁。

**定位判断**：不要做"更便宜的企微 SCRM"（比价必输），也不要做"更安全的微信外挂"（叙事必输）。唯一可持续的位置是：**"给 AI Agent 一双可靠的 Mac 手" + "给敏感行业一个数据不出机的客服方案"**。

## 5. 商业模式设计

### 5.1 五种模式对比

| 模式 | 收入 | 合规 | 交付成本 | 可规模化 | 结论 |
|---|---|---|---|---|---|
| 开源 + 赞助 | 极低 | 高 | 低 | 中 | 做品牌，不做收入 |
| 软件 License（单机） | 中 | 低 | 低 | 高 | 辅线 |
| 私有化交付 | 中高 | 低 | 高 | 低 | 辅线（现金流） |
| SaaS 托管 | 高 | 最低 | 中 | 高 | **不做** |
| **技术授权 / 白标** | **高** | **中高** | **中** | **中** | **主线** |

### 5.2 推荐组合：Open Core + 技术授权 + 受控交付

**开源层（Apache-2.0）**
- 通用眼手 MCP 服务（`desktop_*`）、动作库、观察协议、示例；
- 目的：开发者口碑、生态分发、招聘、把"通用工具"的法律定位坐实；
- 不包含：微信业务规则、轮次引擎、历史库、白名单策略。

**商业层（闭源）**
- Mac 桌面 Agent 引擎 SDK：守护进程 + JSON-RPC/MCP + 许可证 + 白标宿主；
- 定价：5–20 万元/年/客户，或按设备 200–500 元/年走量；
- 目标客户：AI Agent 厂商、RPA 厂商（补 macOS）、垂直 SaaS（客服/电商/财税）、出海工具商。

**受控交付层**
- 微信客服私有化：19,800 元/首年 + 3,980 元/年续费；
- 严格邀请制、不公开营销、不做案例宣传、合同强风险告知；
- 目标：10–20 家设计伙伴，验证真实留存与口碑。

### 5.3 定价与包装

| 方案 | 价格 | 包含 | 目标 |
|---|---|---|---|
| 社区版 | 免费 | 通用眼手 MCP + 文章抓取；不含微信自动回复 | 开发者/技术型个人 |
| 个人版 | ¥1,999/年 | 单机单账号；白名单私聊自动回复；历史库；14 天试用 | 个体运营者 |
| 专业版 | ¥3,999/年 | 多白名单；外部大脑 API；通讯录同步；优先支持 | 2–5 人小团队 |
| 私有化 | ¥19,800 首年 + ¥3,980/年 | 专用 Mac 部署、标定、培训、远程运维（不含硬件） | 中小商家 |
| 技术授权 | ¥50,000–200,000/年 | SDK、白标、源码托管、联合支持 | AI/RPA/垂直 SaaS 厂商 |

**定价原则**：
- 按"设备/账号"定价，不按"席位"（避免被当成企微 SCRM 的廉价替代）；
- 不做"终身买断"，年费制保证持续适配微信版本；

- 私有化报价含"专用机部署"，把硬件与运维成本显性化。

### 7.2 平台规则：确定性违规

《微信个人账号使用规范》（2026-10-15 更新）第 1.2.6 条：

> 通过非腾讯开发、授权的第三方软件、插件、外挂、系统等，注册、登录、使用微信软件及服务或**进行自动化操作**，对微信软件及其组件、模块、**界面**、数据等进行**访问、读取或控制**，或**制作、发布、传播上述工具、方法**等。

三个要点：
1. **"界面"被明文写入**——"只读界面、不碰内存"不再是抗辩；
2. **"制作、发布、传播工具"本身即违规**——卖工具的人和使用工具的人各自违规；
3. **"限制与该主体相关的账号"**——同一实名/设备/支付下的账号可能被连带。

**更直接的违约依据来自《腾讯微信软件许可及服务协议》**：2.3.1 把许可限定为"**非商业目的**"并在"**单一台终端设备**"上使用——把软件用于收费客服、代运营等商业经营，本身即构成违约，无需等到封号或使用外挂；8.3.7 禁止"制作、发布、运营或传播"相关工具，且明确"**无论是否为商业目的**"——这堵死了"我只是免费/开源分享、不赚钱"的抗辩。这也是腾讯主张违约时最省力的条款。

微信安全中心 2026-01-29 公告更进一步，把治理重点写成：

> **违规获取用户敏感数据类**：通过技术手段（如**录音、录屏、截图、辅助服务读取**、破解数据库等）违规获取用户聊天记录、联系人信息等敏感数据……
> **外挂类**：利用**模拟按键、自动化脚本**等手段操控微信，实现"**自动回复**""**管理聊天记录**""**批量加好友**""虚拟定位"等功能。

本产品的技术栈——截图 + OCR、辅助功能/AppleScript 读取界面、模拟键鼠发送、脚本驱动、管理聊天记录、自动回复——**逐项对应**。这不是"踩线"，是"点名"。

**封号概率（专家估计，无官方统计）**：

| 使用强度 | 限制功能/警告 | 永久封号 |
|---|---|---|
| 低频、白名单、少量 | 30–50% | 5–10% |
| 中频、多会话 | 60–80% | 20–30% |
| 高频 + 多开/群发/加粉 | >90% | 显著更高 |

**关键结论**：白名单、自有账号、低频，都**不能**把"违规"变成"合规"；它们只能降低被检测/被处罚的概率。

### 7.3 刑事风险：功能清单的函数

刑法 285 条 3 款打击的是"提供**专门用于**侵入、非法控制计算机信息系统的程序、工具"，司法解释的核心要件是"**避开或者突破安全保护措施**"。

| 产品形态 | 立案风险（专家估计） | 说明 |
|---|---|---|
| 纯 UI 自动化，无 Hook/多开/规避检测，仅自用 | **<5%–10%** | 不满足"突破安全保护措施"核心要件 |
| 同上，但对外销售 | **10%–25%** | 增加"提供工具"外观与平台报案动力 |
| 加入多开/免扫码/批量登录/虚拟定位 | **30%–60%** | 接近已判案例的功能外观 |
| 加入 Hook/注入/数据库破解/协议逆向 | **>70%** | 直接命中"突破安全保护措施" |

**有利事实**：不注入、不 Hook、不解密数据库、使用自身登录态；有出罪/存疑判例（（2019）湘0821刑初73号，法院要求省级以上部门检验"专门用于侵入/非法控制"）。
**不利事实**：平台公告已把"截图/辅助服务读取/模拟按键"单方定性为"绕过微信安全技术措施"；销售规模越大，越容易成为目标。

**判例参考**：
- （2016）粤0105刑初1040号：微信外挂供"微商营销"，3 年缓 5 年；
- 广州南沙"海贼王"外挂案：38 人，主犯 10 年；
- 浙江云和"微营销"外挂案：33 人，涉案 4,000 余万元，1 年至 3 年缓刑；
- "王铁牛"微信外挂案：全国总代理售 30 余万套，3 年 8 个月。

**判断**：纯 UI 路线是"刑事风险最低的违规方案"，但**不是零**；一旦加入"绕过限制"类功能，性质会从违约跳到刑事。这条线必须由产品设计主动守住。

### 7.4 AI 标识与备案

- **标识义务大概率适用**：只要 AI 回复的对象是商家的外部客户（不特定消费者），就落入《深度合成规定》第 17 条第 1 款第（一）项"智能对话模拟自然人"；《人工智能生成合成内容标识办法》2025-09-01 施行后，需在**消息文本**中显式标识（界面标识对方看不见）。
- **不得提供"关闭标识"**：《标识办法》第 10 条禁止为删除/篡改/隐匿标识提供工具或服务。
- **执法已有先例**：2026-04-28，剪映、猫箱、即梦 AI 因标识违规被约谈、责令改正、警告、从严处理责任人。
- **备案**：本地自用可主张不触发；SaaS/多租户/B2B2C 触发大模型登记 + 算法备案，软件方还可能被认定为"技术支持者"参照备案。

**产品影响**：必须在每条 AI 回复中加"〔AI 生成〕"或类似标记。这会削弱"拟人化"体验，但这是红线；**把标识做成产品特色（"可审计的 AI 客服"）反而能建立信任**。

### 7.5 个人信息与数据出境

- 存储的是**第三方（聊天对象）的个人信息**；商家"同意使用工具"不能替代聊天对象本人的同意。需要：告知 + 同意/其他合法性基础 + 敏感信息单独同意 + 委托处理协议 + PIA + 最短必要 + 境内存储。
- **本地存储是优势，但不是豁免**：仍构成个人信息处理，仍需合规底座。
- **数据出境**：默认接入 OpenAI/Codex 等境外模型 = 聊天内容出境，属红色风险；必须默认使用境内已备案模型（DeepSeek/通义/豆包/文心等），并确认"不用于训练"。
- **当前默认 `codex-exec` 是境外模型**，这是一个必须立即修改的配置级风险。

### 7.6 合同与责任

- **免责条款不能覆盖故意/重大过失**（民法典 506 条）；"封号概不负责"若未显著提示，可能不成为合同内容；若被认定不合理免除主要义务，无效。
- **建议**：风险告知书（单独签字）+ 责任上限（不超过年费）+ 用户保证合法用途 + 禁止转售 + 数据处理附件（DPA）+ 退款政策。
- **主体**：个体工商户/工作室起步即可；不要为了避责专设离岸壳（可能被认定逃避责任）；收入到 100 万+ 再考虑有限公司。
- **不要做 SaaS 托管**：责任主体从用户转移到服务方，风险 ×3–5，且触发 ICP/EDI、等保、备案一整套义务。

### 7.7 合规前置条件（若坚持做微信场景）

| 级别 | 条件 |
|---|---|
| P0（不做就不能卖） | 删净多开/免扫码/虚拟定位/批量加好友/规避检测；删除"关闭 AI 标识"；默认显式标识；境内模型；DPA + 告知同意链 + PIA；产品更名；风险告知书 + 责任上限 |
| P1（3 个月内） | 大模型登记/算法备案（视形态）；ICP 备案；内容安全机制；用户协议 + 禁止用途清单 |
| P2（持续） | 季度合规自查；客户准入（排除高风险行业）；封号应急预案；监管沟通；网络安全责任险 |

### 7.8 三条红线

1. **不做协议/Hook/注入/数据库破解**——这是刑事定性的分水岭。
2. **不做多开/群控/批量加好友/群发营销/虚拟定位/规避检测**——这是"专门用于控制"的外观。
3. **不做 SaaS 托管代运营**——这是责任放大的加速器。

## 8. 战略路径选择

### 8.1 四条路径

| 路径 | 做什么 | 3 年收入 | 合规 | 刑事风险 | 周期 | 适合 |
|---|---|---|---|---|---|---|
| **A. 内部自用/开源** | 不卖微信自动化；开源通用眼手 | 0 | 低 | 低 | 立即 | 技术品牌/长期 |
| **B. 受控工具授权（灰）** | 卖单机/私有化，邀请制，不营销 | 100–400 万 | 违反平台 | 10–25% | 2–3 个月 | 快速验证现金流 |
| **C. 技术授权/白标（横向）** | 卖 Mac 桌面 Agent 引擎 SDK | 100–500 万 | 中高 | <10% | 3–6 个月 | **推荐主线** |
| **D. SaaS 托管/公开卖工具** | 代运营/公开售卖 | 名义高 | 最低 | 30–60% | 立即 | **不建议** |

### 8.2 推荐：C 为主线，B 为辅线

**为什么 C 是主线**：
- **法律定性最好**：通用桌面工具不是"专门用于微信"，更接近影刀 RPA 的公开售卖形态；
- **TAM 更大**：任何 Mac 桌面自动化（客服、电商 ERP、财税、设计、测试）都可覆盖；
- **与 MCP/Agent 生态同向**：2025–2026 年最大的技术叙事就是 Agent 需要"手"；
- **代码复用 80%**：`desktop_*`、拟人动作、观察协议、幂等、宿主 App 都是现成的；
- **客单价高**：5–20 万/年/客户，3 家客户 ≈ 100 个个人版用户。

**为什么 B 是辅线而不是主线**：
- 现金流最快（设计伙伴预付款），能验证真实需求；
- 但公开售卖 = 确定违规 + 品牌不可逆；只能"邀请制、不宣传、不承诺、不规模化"；
- 一旦 B 的收入占比超过 50%，公司就被锚定在灰色赛道，C 的客户（企业法务会尽调）会远离。

**执行原则**：
1. **对外只讲 C**：官网、GitHub、销售材料都以"Mac 桌面 Agent 引擎"为主语，微信只是 demo 之一。
2. **B 不出现在公开渠道**：不做案例、不做投放、不参加展会；合同用"定制开发/技术服务"而非"微信自动化工具"。
3. **两条线共用一套代码，但分仓/分许可证**：通用层开源，垂直层闭源商业许可。
4. **12 个月后复盘**：若 C 拿到 ≥3 家付费授权，全力转 C；若 C 失败而 B 现金流稳定，再决定是否接受"小而灰"的定位。

### 8.3 决策树

```text
你的目标是什么？
├─ 想验证"能不能赚钱"、能接受法律风险
│   └─ 走 B：3 个月补 P0 → 3–5 个设计伙伴 → 1,999–19,800 定价 → 控制在 100 家以内
├─ 想做一个长期、可公开、能融资/被收购的资产
│   └─ 走 C：3–6 个月产品化 SDK → 2–3 个技术授权客户 → 开源通用层
├─ 只想自用/技术影响力
│   └─ 走 A：修 P0 → 开源 → 接定制项目
└─ 想快速放大收入
    └─ 不要走 D（SaaS）；这个赛道的规模化与合规性负相关
```

### 9.1 定位与叙事

| 面向 | 一句话 | 不要说 |

### 9.3 销售流程

```text
内容/开源曝光 → 下载试用（14 天/50 条）→ 15 分钟诊断（环境/微信版本/权限）
→ POC（1 个白名单会话，7 天）→ 成交（个人版/私有化）→ 30 天回访 → 续费
```

**关键动作**：
- 售前**强制环境自检**（系统版本、微信版本、窗口尺寸、权限、专用机），不满足直接劝退，降低退款率；
- POC 只开 1 个白名单会话，设每日上限，**默认人工确认发送**；
- 合同附**风险告知书**，明确"不承诺防封、不承诺送达、不承诺完整历史"；
- 30 天回访收集"自动回复占比、人工接管率、封号情况"，作为续费与产品迭代依据。

### 9.4 内容策略（30 条选题方向）

1. 技术向："我们如何在不碰协议的前提下读微信界面"（AX + OCR + 双帧校验）
2. 对比向："Mac 上的微信自动化，为什么比 Hook 方案更安全（但也更慢）"
3. 场景向："医美客服的 7 个高频问题，AI 能接几个？"
4. 踩坑向："微信 4.1.15 升级后，我们的适配踩了哪些坑"
5. 合规向："AI 客服必须加标识：我们为什么把'〔AI 生成〕'做成产品功能"
6. 数据向："本地 SQLite vs 云端 SaaS：客户聊天记录该放哪"
7. 开源向："把 Mac 眼手开源后，我们收到了哪些需求"

### 9.5 种子客户计划

- **数量**：10 家（医美 3、教培 3、保险 2、房产 2）

- **价格**：首年 9,900 元（五折），续费恢复 19,800
- **目标**：验证"周活跃、自动回复占比 ≥40%、人工接管率 ≤30%、封号 ≤1 家/季度"
- **退出机制**：不满足环境/不接受条款的客户直接劝退，不赚"最后一笔"

## 12. 结论

**三句话：**

1. **这是一个"技术资产 > 商业形态"的项目。** 眼手、轮次、幂等、本地历史、外部大脑协议都是真东西；但把它们装进"微信自动回复机器人"的外壳里，商业价值会被合规风险吃掉大半。
2. **最好的变现方式不是卖微信工具，而是卖"Mac 桌面 Agent 引擎"。** 同一套代码，换一个品类、换一个叙事、换一批客户，法律风险降一个量级，TAM 大一个量级。微信客服保留为邀请制交付，做现金流和 know-how，不做品牌。
3. **如果一定要走灰色路径，就把预期降到"100–400 万/年的小生意"，并接受 10–25% 的刑事风险与确定性的平台违规。** 不要做 SaaS、不要多开、不要群发、不要规模化；控制客户数、控制宣传、控制功能清单。

**最后一句**：这个项目最稀缺的不是代码，是**"在不稳定 UI 上把可靠性做到可审计"的工程能力**。把它用在合规的赛道上，价值远大于在微信灰产里卷价格。
