# wechat-mcp 合规商业化方案

> **版本** v1.0 ｜ **日期** 2026-11-10 ｜ **关系**：本方案替代《[商业化分析报告](docs/business/商业化分析报告.md)》第 8 章的路径建议；原报告作为市场/合规/产品底稿保留。
> **一句话**：不修补"个人微信自动化"这条灰色路径，而是换轨到 **微信客服官方 API + 本地化 AI 客服中台**；同一套 AI 大脑、历史库、轮次协议、MCP 接口全部保留，只替换"手和眼"。
> **性质**：产品与商业方案，不构成法律意见；上线前需律师出具正式意见并向属地网信办书面确认备案口径。

## 0. 执行摘要

### 0.1 结论

**前版报告的红线结论没有折中方案：个人微信的读屏、模拟点击、自动回复，在平台规则层面确定违规，无法通过"白名单/自有账号/低频/本地化"洗白。** 因此本方案不做"更隐蔽的自动化"，而是把通道换成腾讯官方唯一认可的自动化路径——**企业微信·微信客服（WeCom Kf）API**——并把产品重新定义为：

> **给中小企业的「微信生态 AI 客服中台」：官方 API 接入、本地/私有化部署、自带模型、人工可接管、全链路可审计。**

### 0.2 产品矩阵

| 产品 | 内容 | 合规性 | 角色 |
|---|---|---|---|
| **KfDesk（主产品）** | 微信客服官方 API 的 AI 自动回复 + 人工接管 + 知识库 + 审计；Docker/macOS 私有化部署 | ✅ 官方 API | 收入主力 |
| **会话存档副驾驶（Pro 模块）** | 读取企业已购买的企微会话存档，生成推荐回复/质检评分，**人工发送** | ✅ 官方 API + 双告知 | 高客单模块 |
| **个人微信人工中转副驾驶** | 用户复制客户消息 → AI 生成草稿 → 用户自己粘贴发送；**不读屏、不模拟操作** | 🟡 低风险（不接触微信进程） | 引流/过渡 |
| **Mac 桌面 RPA SDK** | 通用 macOS 眼手，仅用于企业内部流程/非微信应用；EULA 明确排除个人微信自动化 | 🟡 通用工具 | 可选资产变现 |

**明确不做**：个人微信自动收发、群控/多开、协议/Hook/注入、批量加好友、群发营销、SaaS 托管代运营、任何"防封/规避检测"功能。

### 0.3 关键数字

| 维度 | 数字 | 说明 |
|---|---|---|
| 合规通道 | 微信客服 API：`kf_msg_or_event` 回调 → `sync_msg` 拉取 → `send_msg` 回复 | 腾讯官方；企微社区明确"AI 接管不违规" |
| 通道成本 | 微信客服免费；企微认证约 300 元/年；未认证企业累计限 100 位客户，已验证未过期每天 100 位，认证后无上限 | 官方帮助中心 |
| 存档成本 | 会话存档 2026-01-22 起 400 / 900 / 1,800 元/人/年（办公/服务/企业） | 官方调价公告 |
| 建议定价 | 标准版 29,800/年；专业版 49,800/年；实施 15,000 起；白标 98,000/年 | 本方案 |
| MVP 工期 | 79–122 人日（1 人约 4–5.5 个月；2 人约 2–3 个月） | 含微信客服适配器、控制台、部署包、测试验收 |
| 三年收入（中性） | 61 → 212 → 534 万元；第 3 年净利率 27% | 财务模型 |
| 第一年 | 收入 61 万、亏损 22 万；需要 40–60 万 runway | 中性情景 |
| 核心差异化 | 私有化 + BYO 模型 + 数据不出内网 + MCP/Open API + 审计 | 与 SaaS 竞品错位 |

### 0.4 为什么这次是合规的

不是因为"我们更小心"，而是因为**通道本身被平台允许**：

- 腾讯云 2026-08 的公开文章明确："官方唯一认可的自动化途径，只有企业微信客服。通过企业微信客服的官方 API，可以合规地实现程序自动收发消息、AI 智能应答、关键词回复等功能。"（[来源](https://cloud.tencent.com.cn/developer/article/2730298)）
- 企业微信开发者社区对"完全使用 AI 接管企业微信客服是否违规"的官方答复是："这个没有违规的说法……具体回答内容企业要做好风控处理，注意敏感词处理。"（[来源](https://developer.work.weixin.qq.com/community/question/detail?content_id=16699640684019953116)）
- 微信客服的消息有官方 `msgid`、方向、时间、发送状态，**不再依赖 OCR 猜**——这同时解决了原产品最大的技术缺陷。

**代价要说清楚**：合规方案**不能**自动回复个人微信好友。微信客服只覆盖"客户从搜一搜/小程序/公众号/视频号/线下码进入客服"的新入口。原产品最核心的"个人号存量好友自动化"需求，在合规框架下无解——这是必须放弃的部分。

## 1. 为什么必须换轨

### 1.1 三条不可逾越的红线

| 红线 | 事实 | 结论 |
|---|---|---|
| 平台规则 | 《微信个人账号使用规范》1.2.6 禁止"自动化操作""对界面/数据访问、读取或控制""制作、发布、传播工具"；2026-01-29 公告点名"截图、辅助服务读取、模拟按键、自动回复、管理聊天记录" | 个人微信 UI 自动化**确定违规**，白名单/自有账号不构成抗辩 |
| 软件许可 | 《腾讯微信软件许可及服务协议》2.3.1 限定"非商业目的、单一台终端"；8.3.7 禁止"运营或传播工具，无论是否为商业目的" | **商业化使用本身即违约** |
| 刑事边界 | 刑法 285 条 3 款 + 法释〔2011〕19 号："避开或突破安全保护措施""专门用于侵入/非法控制" | 纯 UI 自动化风险较低（<10%），但**卖工具 + 多开/规避检测**升至 30–60%；不值得赌 |

### 1.2 为什么"打补丁"不成立

- 删除"自动发送"只保留"读屏 + 草稿"→ 仍违反"读取界面"；
- 删除"读屏"只保留"模拟点击"→ 仍违反"自动化操作"；
- 改成"本地运行、不联网"→ 平台规则不因部署位置而改变；
- 改成"开源、免费"→ 8.3.7 明确"无论是否为商业目的"；
- 加"用户自行承担风险"条款→ 不能把平台违规变成合规，也不能免除卖方的"制作、传播工具"责任。

**唯一干净的切割方式：不碰个人微信客户端。**

### 1.3 合规通道的边界（必须写进销售材料）

| 能做 | 不能做 |
|---|---|
| 微信客服（kf）自动回复/人工接管 | 个人微信好友 1:1 自动回复 |
| 公众号客服消息（48 小时窗口）AI 回复 | 个人微信群/朋友圈自动化 |
| 企微会话存档只读 + AI 推荐回复（人工发送） | 企微员工账号自动收发（官方不允许机器人操控成员账号） |
| 企业内部流程 RPA（ERP/Excel/浏览器） | 任何规避平台检测、多开、群控 |

## 2. 合规产品定义

### 2.1 一句话定位

> **KfDesk（工作名，需商标检索）：装在你自己服务器/Mac 上的微信客服 AI 中台——官方 API 接入、自带模型、数据不出内网、每条 AI 回复都可审计。**

### 2.2 三个渠道

| 渠道 | 接入方式 | 消息能力 | 适用 |
|---|---|---|---|
| **微信客服（Kf）** | 自建应用 + 回调 `kf_msg_or_event` + `sync_msg`/`send_msg` | 文本、图片、文件、菜单、小程序卡片；官方 msgid/状态 | 主渠道；客户从搜一搜/小程序/公众号/视频号/线下码进入 |
| **公众号客服消息** | 认证服务号 + 客服消息接口 | 48 小时内文本/图片/图文 | 已有公众号的客户；P1 |
| **企微会话存档（只读）** | 企业购买会话存档 + 员工/客户双告知 + 官方 API | 读取历史会话；**不能代发** | Pro 模块；金融/医美/教培等强合规行业 |

### 2.3 能力清单

**MVP（P0）**
- 微信客服账号接入：corp_id / secret / open_kfid / 回调 token / EncodingAESKey；
- 消息同步：回调触发 + `sync_msg` 游标拉取，断点续传、去重；
- 发送：文本、图片、文件、菜单；失败重试与终态记录；
- 会话编排：一轮一问、静默聚合、去重、超时、转人工；
- AI 回复：BYO 模型（DeepSeek/通义/豆包/文心等）、系统提示词、FAQ、AI 标识；
- 人工接管：关键词/低置信度/情绪/超时转人工，坐席工作台；
- 知识库：文档导入、切分、检索（先关键词/FTS，后向量）；
- 审计：每条消息的输入、模型、输出、标识、发送结果；
- 部署：Docker Compose + macOS App；备份/恢复；健康检查；
- 安全：secret 存 Keychain/加密、DB 加密、RBAC、日志脱敏。

**P1**
- RAG 向量检索、意图路由、多业务线/多客服组；
- 公众号客服消息渠道；
- 统计看板（响应时长、解决率、转人工率、AI 占比）；
- SLA、告警、升级包、灰度发布；
- 与 CRM/订单系统通过 HTTP tool/MCP 集成。

**P2**
- 会话存档副驾驶（推荐回复/质检评分）；
- 私有化双机热备、审计导出、等保加固包；
- 白标/OEM、渠道管理后台；
- 多语言/出海版本（如后续做 WhatsApp Business API）。

## 3. 目标客户与价值主张

### 3.1 ICP

**10–50 人规模、5–30 个客服、日咨询 100–1,000 条、已有微信客服或公众号入口、对数据位置敏感的中小企业。**

优先行业（按付费意愿）：

| 行业 | 为什么 | 特别注意 |
|---|---|---|
| 医美/口腔/植发 | 线索成本高（8,000–12,000 元/人）、夜间咨询多 | 医疗广告合规，话术需人工复核 |
| 教培/知识付费 | 私域转化主路径、重复问题多 | 退费/承诺话术风控 |
| 保险经纪 | 长周期跟进、合规要求高 | 金融双录/存档 |
| 家装/房产 | 单客价值高、线索跟进密集 | 区域性强 |
| 本地生活连锁 | 高频、标准化 | 价格敏感 |
| 电商售后 | 重复问题多、峰值明显 | 与订单系统集成 |

### 3.2 价值主张

| 痛点 | 现状 | KfDesk |
|---|---|---|
| 夜间/峰值漏消息 | 人工轮班，成本高 | 7×24 AI 首响，复杂问题转人工 |
| 重复问题占 60%+ | 客服复制粘贴 | 知识库 + 意图路由，AI 直接答 |
| 数据不能出内网 | SaaS 不敢用 | 私有化部署，数据留本地 |
| 模型成本不可控 | SaaS 按条计费/加价 | BYO 模型，按量付费给模型厂商 |
| 质检靠抽听 | 事后、抽样 | 全量记录 + AI 质检评分 |
| 平台封号风险 | 灰色工具随时归零 | 官方 API，无封号风险 |

### 3.3 ROI 算法

- 1 个客服年成本 7.2–18 万元（私域岗 6,000–14,999 元/月，含社保）。
- KfDesk 标准版 29,800 元/年 ≈ **0.2–0.4 个人力**。
- 若 AI 承接 50% 首响、人工只处理复杂问题，ROI 通常 3–6 个月。
- 对已有会话存档的企业，Pro 模块把"合规成本"转成"质检/推荐价值"，边际决策更快。

## 4. 系统架构

### 4.1 架构图

```text
微信客户
  └─ 微信客服入口（搜一搜/小程序/公众号/视频号/线下码）
        └─ 腾讯微信客服（官方）
              ├─ 回调 kf_msg_or_event ──→ [Connector Relay]（仅事件路由，不存正文）
              │                                   └─ 客户内网 Agent（出站长连接）
              └─ sync_msg / send_msg ←──────────────┘
                    │
                    ▼
        ┌─────────────────────────────────────────────┐
        │ KfDesk（客户服务器 / Mac，Docker 或原生 App） │
        │  ├─ 渠道适配器：wecom_kf / wecom_mp          │
        │  ├─ 会话编排：轮次、去重、超时、转人工        │
        │  ├─ AI 大脑：BYO 模型 + 外部大脑 MCP         │
        │  ├─ 知识库：文档/FAQ/向量检索                │
        │  ├─ 人工工作台：Web / macOS App              │
        │  ├─ 历史库：SQLite/Postgres，加密            │
        │  ├─ 合规：AI 标识、内容过滤、审计、留存      │
        │  └─ 开放接口：MCP / HTTP，接 CRM/订单        │
        └─────────────────────────────────────────────┘
```

### 4.2 关键设计决策

1. **回调 relay 只做事件路由，不碰消息正文。** 腾讯要求回调地址公网可达；中小客户通常没有公网 IP。方案：厂商提供一个无状态 relay，收到回调后只把 `corp_id/open_kfid/事件 token` 通过客户出站长连接推给本地 Agent，本地 Agent 再直接调用 `sync_msg` 拉正文。**正文不经过厂商云**，这是"数据不出内网"的技术保证，也是销售话术。
2. **回调优先，短轮询兜底。** 有公网/relay 时用 `kf_msg_or_event` 触发；极端情况下可短轮询 `sync_msg`，但需实测腾讯限频与时效，默认不推荐。
3. **BYO 模型。** 客户用自己的 DeepSeek/通义/豆包/文心 API Key，费用直接付给模型厂商；KfDesk 不转售 token、不赚差价。这既降低客户成本，也把"生成式 AI 服务提供者"的责任留在客户侧（合同明确）。
4. **默认人工可接管。** AI 不是"全自动无人值守"，而是"首响 + 草稿 + 转人工"。高风险行业默认"AI 草稿 + 人工确认发送"模式。
5. **官方 msgid 驱动。** 用 `msgid` 去重、排序、对账，不再依赖屏幕像素；发送状态用官方返回值 + 事件回调双向确认。
6. **单租户。** 一个客户一套部署、一套数据库。不做多租户 SaaS，避免 ICP/等保/数据混合责任。

### 4.3 部署形态

| 形态 | 适用 | 说明 |
|---|---|---|
| **Docker Compose（主）** | 有 IT 的中小企业 | Linux 服务器/云主机；一条命令起服务；反向代理可选 |
| **macOS App（辅）** | 无 IT、已有 Mac 的小客户 | 复用现有宿主 App 的权限/常驻能力；但不再需要辅助功能/屏幕录制 |
| **双机热备（P2）** | 大型客户 | 主备 + 共享存储/复制 |

## 5. 合规设计（by design）

### 5.1 合规矩阵

| 义务 | 产品措施 | 证据/交付物 |
|---|---|---|
| 微信平台规则 | 只用官方 API；不读屏/不模拟/不注入；EULA 禁止个人微信自动化；发布物不含相关二进制 | 架构图、EULA、发布清单 |
| 生成式 AI 标识 | 每条 AI 消息末尾默认追加"〔AI 生成〕"；界面常驻"AI 客服"标识；**不提供关闭开关**；审计记录标识版本 | 截图、配置项、审计日志 |
| 生成式 AI 备案/登记 | 私有化 + 客户自持模型账号；合同明确客户为服务提供者；提供备案材料清单与协助 | 合同条款、备案清单 |
| 个人信息保护 | 本地部署；DB 加密；最小必要；留存期限；删除接口；访问控制；日志脱敏；PIA/DPA 模板 | 隐私政策、DPA、PIA 模板、功能截图 |
| 数据出境 | 模型 endpoint 白名单（仅境内）；禁止境外默认；配置校验/启动自检 | 配置校验代码、启动报告 |
| 增值电信 | 只卖软件许可 + 实施服务；不做 SaaS、不代收通信费、不托管账号 | 合同、发票类目 |
| 等保/数安 | 提供等保加固指南（日志、权限、审计、加密）；客户自行定级备案 | 加固手册 |
| 消费者权益 | 人工接管、投诉入口、AI 标识、禁止承诺性话术模板 | 话术模板、工作台 |
| 特殊行业 | 医疗/金融/教育模板 + 敏感词 + 强制人工复核 | 行业包、规则文件 |
| 会话存档 | 仅对接企业已购存档；不绕过双告知；客户不同意则不可用 | 接入检查清单 |

### 5.2 三条产品红线

1. **不接触个人微信客户端**：不读屏、不截图、不模拟键鼠、不注入、不读数据库。
2. **不做"无人值守全自动"**：默认人工可接管；高风险行业默认人工确认发送；不做"AI 冒充真人"。
3. **不做多租户 SaaS**：只做私有化/单租户；不托管客户账号、不代运营。

### 5.3 合同与主体

- **合同结构**：软件许可（年度订阅）+ 实施服务 + 运维支持；附 DPA、风险告知书、禁止用途清单、SLA。
- **责任上限**：不超过过去 12 个月实际支付费用；不承担间接损失/利润损失；故意/重大过失除外（法律强制）。
- **主体**：个体工商户/工作室起步可签软件许可与技术服务；收入稳定后设有限公司。**不建议**为规避责任设离岸壳。
- **资质**：软件著作权登记（招投标/资质加分）、商标（产品名）、可选 ISO 27001/等保加固服务。

## 12. 结论

1. **合规方案不是"把灰色工具改小一点"，而是换通道、换客户、换叙事。** 微信客服官方 API 是腾讯唯一认可的自动化路径，也是这个项目唯一能公开卖、长期卖的底座。
2. **代价是放弃"个人微信存量好友自动化"**——这是原产品最值钱、也最违规的部分。接受这个代价，才能换来可签合同、可开发票、可融资、可长期维护的资产。
3. **技术资产大部分保留**：AI 大脑、轮次、历史库、MCP/Open API、宿主 App、备份恢复都能复用；要重写的是"手和眼"（适配器）和"合规层"。
4. **先做 3 家设计伙伴，再决定是否铺销售。** 16 周 MVP、40–60 万 runway、第 1 年 12–15 家付费——这是一个可验证、可止损的路径。
