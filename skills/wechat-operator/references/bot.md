# 白名单客服 Bot

用户明确指定自动回复对象及模型规则后，才启用自动发送。沿用当前会话已经确认的授权，不为每条允许的消息重复询问；授权不扩展到其他联系人、群聊或好友申请。

当前项目提供两种入口：

- `scripts.wechat_bot`：有时限、带唯一测试前缀、最多回复一次的验证程序。
- `scripts.wechat_bot.service`：常驻多私聊白名单服务，无测试前缀；`scripts.wechat_bot.control`用于安装、状态、启动和停止。先确认项目工作目录和本机配置，不把这几个Python模块当成MCP工具。

服务的实际行为：

1. 初次启动只建立可见气泡基线，不回复旧记录。
2. 只有完整标题匹配指定私聊、视觉候选判为左侧入站、连续两次采集一致且有连续锚点时，才交给模型。
3. 模型只生成文字，不决定收件人，也不能调用微信、应用、命令或搜索工具。没有业务知识库时，不编造商品、订单或退款信息。
4. 生成后再次采集；聊天已变化就舍弃旧回复。发送复用原有标题/输入读回及稳定幂等键，结果未知不换键重发。
5. 忽略右侧自身回显；限流时保留待处理输入。模型/发送阶段不确定会暂停，检查持久日志后再处理，不通过清空记录强行重试。

这是当前暗色主题、880×640窗口、1倍像素比例的受控实现。亮色、缩放、窗口大小或布局不匹配时停止；图像启发式不是微信消息ID或发送者身份验证。多个精确私聊白名单可用；群聊自动回复、好友请求处理仍未启用。

操作前检查`control status`及配置中的精确白名单。服务开启时占用专用GUI宿主的唯一MCP连接；不要从另一个客户端竞争同一个桌面。诊断图像保存在测试机私有目录，模型接收所选会话的文字上下文，以及按能力配置提供的图片/文件提取内容。

启动和停止影响后续自动发送，按用户已授权的范围执行。停止命令同时禁用登录自启；状态中的`watching`表示采集运行，不等于平台消息已验证或模型配额永远可用。`triggered`与客户端回显均不代表送达。


模型可选 `codex-exec` 或 `model_config.backend=openai-compatible`。兼容接口配置 `base_url`、`model`、`api_key_env`、`supports_images`，详细结构见项目 `docs/allowlist-bot.md`。DeepSeek 默认读 `DEEPSEEK_API_KEY`，其他兼容接口默认 `OPENAI_API_KEY`，可用 `api_key_env` 自定义。显式 `api_key_file` 优先，文件必须为当前用户的 600 私有文件。launchd 服务不读取终端 `.zshrc`，需在其环境中注入变量后重启；不让用户在聊天中粘贴密钥。未配置密钥或未完成真实调用时不能称为已接通该提供方。切换提供方不改变自动回复白名单；不因错误自动重试付费请求或静默降级模型。


配置统一位于 `~/.WeChatRPABot/config.json`。`allowlist` 支持多个 `{recipient, kind:"private"}`；`ignorelist` 支持多个 private/group，排除优先。由于桌面不能区分同名群/私聊，命中同标题的任何排除项都阻止该目标。规则在轮询和模型/发送前重读，错误配置停止处理；不得给未在实际白名单内的目标发送。每会话状态位于 `state_dir/sessions/<hash>/`，旧流水迁移保留幂等和暂停状态，不能因升级清空重发。
