# 环境与定位

## 首次接入

确认实际运行机器、微信版本、登录状态、可见窗口和 MCP 执行宿主。当前桌面实现为 macOS，不能宣称已有 Windows worker。账号配置是本地路由，不是微信登录认证。

屏幕录制、辅助功能及 AppleScript 自动化权限属于实际执行进程/宿主。SSH 能连接不等于 SSH 进程获得 GUI 权限；使用专用 GUI 宿主时通过其已配置的连接操作，不另从 SSH 启动一份桌面控制程序。

系统设置已勾选而检查仍失败时，先比对运行路径、bundle ID、进程和签名，以及 GUI 与 SSH 的执行上下文。不要让用户反复刷新或全局重置权限。业务更新尽量保持已授权 GUI 宿主身份不变。

## 窗口与屏幕

- 每次定位使用当前可见窗口及实际几何；不可见窗口、其他 Space、最小化和内容白屏需要分别诊断。
- 显示器插拔、缩放、窗口布局或输入框高度改变后，旧坐标可能失效。重新定位和核验；可读性不足时停止，不能仅凭窗口存在就点击。
- 当前默认仍有固定布局偏移。stream 的窗口相对区域 profile 不是已完成的自动标定；不要把一台机器的区域配置直接作为另一台机器的可靠配置。
- 驱动默认 `legacy`；当前 `stream` 实现要求 macOS14及以上，旧Mac使用兼容路径。明确启用 stream 后的失败应报告，不假装静默回退已通过。

## 操作可视化

`wechat_overlay`提供窗口角标、跟随实际鼠标的指针及点击光圈。角标表示窗口已定位，不表示接收人身份已验证。浮层不抢焦点、不接收点击，截图识别前隐藏；系统截图未包含浮层不能单独证明它没有显示。

浮层为可选组件，`WECHAT_MCP_OPERATION_OVERLAY=0`可关闭。诊断失败或浮层关闭不应改变实际业务动作的成功/失败含义。

## 无可用 MCP 时

说明缺少的服务或工具，并按用户请求定位项目的安装说明。不要只因 Skill 已加载就假设 MCP 已运行；也不要为了读取公众号文章要求桌面权限。安装后的 initialize/tools/list 自检证明协议可用，不能替代真实收发验证。
