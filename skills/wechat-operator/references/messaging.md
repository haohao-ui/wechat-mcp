# 文字收发

## 账号与目标

1. 发现 MCP 工具；工具名可能带宿主前缀。调用 `list_accounts`，选择用户指定绑定；多账号或同名目标不明确时先澄清。
2. 读取使用 `get_messages`，发送文字使用 `send_message`，发送本机文件使用 `send_file`（`path` 为宿主电脑上的绝对路径，只允许桌面、文稿、下载文件夹，≤10MB）；优先统一工具，不同时调用旧名称重复执行操作。
3. 私聊和群聊都使用精确 `recipient`。窗口位置、联系人缓存和搜索结果只是定位线索，最终须通过完整标题核验。群标题的成员数量后缀按驱动规范处理，不允许用模糊前缀代替身份。

以下为参数形状，替换为用户指定账号、目标和正文后再使用：

```json
{"platform":"wechat","account_id":"local","recipient":"测试联系人"}
```

上述参数用于 `get_messages`；读取结果通常为 OCR `text_lines`。`coverage=visible_only`、`direction=unknown`、无可靠消息ID时，不把文字行当作完整、已去重或已判定方向的消息。

## 发送

```json
{"platform":"wechat","account_id":"local","recipient":"测试联系人","message":"用户授权的正文","idempotency_key":"本次发送意图的稳定唯一键"}
```

参数用于 `send_message`。发送路径负责打开目标、标题核验、输入正文读回和再次标题核验。任一环节失败即停止，不通过其他点击方式绕过。`send_file` 同样打开目标并核验标题，先清空输入框，粘贴文件后 OCR 输入框确认出现该文件名，再次核验标题才回车；同一幂等键换了文件或文件已被修改会被拒绝。结果同样只是 `triggered`，不代表送达。

`get_send_status` 使用相同账号与 `idempotency_key` 查询。先前请求已触发或结果未知时，不生成新键再次发送。恢复剪贴板或界面状态不能作为重发理由。

## 验收与结果

- `triggered` 说明客户端动作已触发；`delivery=unknown` 必须保留，不能报告“对方已收到”。
- OCR 中出现正文还可能是输入框、历史记录或重复文字，单独不足以证明新发送成功。需要客户端气泡证据；视觉人工确认与程序自动识别应分别说明。
- 不为了测试读取而从同一个账号再发送一条消息。真实入站验证需要对方回复，并分别记录文字识别与方向证据。
- 群聊先核验完整群标题，再操作；未实现发送者解析时，不根据头像位置、预览或名字猜测群成员。不要把私聊样本当作群聊验收。
- 好友申请和加好友目前没有已实现的对应工作流；说明缺口，保留用户目标供后续开发，不模拟完成结果。
