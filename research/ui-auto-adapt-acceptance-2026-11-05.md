# 微信界面自动适配验收记录（2026-11-05）

环境：微信 4.1.15。远端测试机 macOS 12.7.6 x86_64（1 倍屏）；本机 macOS 27.2（内置 Retina）。联系人仅测试会话（示例联系人甲、文件传输助手）。

## 自动化测试

- `tests/test_native_frames.py`：10 个脱敏截图样本（1 倍/Retina × 深色/浅色，浅色样本与同位置深色样本逐条比对方向、类型、文字），加未知主题拒绝样本，全部通过。
- 机器人 Python 测试与历史功能测试全部通过。

## 真机验收（远端 1 倍屏）

| 项 | 结果 |
|---|---|
| 深色：文字收发、未读红点点击切换 | 通过 |
| 运行中切换到浅色，不重启继续回复，方向正确 | 通过（切换时重建一次基线） |
| 手动拉大窗口后自动调回 880×640 并回复 | 通过 |
| 最小化后自动恢复窗口并回复 | 通过（修复重连路径后） |
| 图片、文件消息回复 | **不稳定**：图片加载中像素变化、高媒体把锚点挤出画面，触发断档只记录不回复。另开任务（改消息指纹） |

## 本机 Retina

- ScreenCaptureKit 截图 + 归一化：worker `sessions` 操作成功（0.49 秒），Vision 冷启动预热约 27 秒。
- 深色/浅色 Retina 截图解析结果与 1 倍一致。
- 未在本机跑完整收发：本机登录测试号会把远端挤下线（微信同一账号只允许一台电脑登录）。

## 验收中发现并修复

- 已保存游标使用旧主题名，服务启动即退出 → 兼容读取。
- 空画面被当作基线，下一帧旧消息被当新消息生成回复（发送恰好失败） → 空基线视为未建立基线。
- 发送后核对遇到断档会暂停联系人 → 按断档规则重建基线。
- 最小化后重连只走 MCP 搜索，永远失败 → 先复用运行中的 worker 恢复窗口并点击打开。
- 远端工具链为 Swift 5.7 → ScreenCaptureKit 分支按编译器版本条件编译。

## 遗留

- 图片/文件（含一次多张）连续性：另开任务。
- "WeChat RPA Test" 环境检查窗口会挡住微信：放入"一键安装"待办。
- 长回复折行导致回显确认（`client_echo_observed`）为 false，不影响收发。
